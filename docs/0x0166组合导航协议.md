# 0x0166 组合导航帧协议说明

本文档描述自研 AA55 二进制帧容器中 **ID = 0x0166** 的「组合导航（坐标系融合结果）」协议，以及同一线协议 ID 下按 payload 长度分流出的「倾斜测量」变体。

对应代码：

- 协议定义：`modules/parse/parser/core/protocoldefs.h`
- 帧切分/校验/字段解析：`modules/parse/parser/core/frameparser.cpp`
- 协议注册（字段名 / CSV 表头 / 导出格式）：`modules/parse/parser/single/protocolregistry.cpp`
- 数据分析侧转换：`modules/analysis/core/converter.h`

---

## 1. 帧容器格式

所有自研二进制帧共用统一容器，**小端（Little-Endian）**：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0 | 1 | Sync1 | 固定 `0xAA` |
| 1 | 1 | Sync2 | 固定 `0x55` |
| 2 | 2 | ID | 协议号，u16 小端 |
| 4 | 2 | Length | **payload 字节数**，u16 小端（不含帧头与校验） |
| 6 | Length | Payload | 数据区 |
| 6+Length | 4 | CRC32 | 校验值，u32 小端 |

- 帧头固定 6 B，帧尾固定 4 B。
- 总帧长 = `6 + Length + 4`。
- 0x0166（94 B payload）总帧长 = `6 + 94 + 4 = 104` 字节，帧头字节序列为：

```text
AA 55 66 01 5E 00 | <94 字节 payload> | <4 字节 CRC32>
      ^ID=0x0166  ^Length=0x005E=94
```

## 2. 校验规则

### 2.1 CRC32（主校验）

- 多项式：`0xEDB88320`（反射式 IEEE 802.3 查表实现）
- 初值：`1`（注意：**不是** `0xFFFFFFFF`）
- 最终异或：**无**
- 覆盖范围：`AA 55 + ID + Length + Payload`，即从帧首字节起 `6 + Length` 字节；帧尾 4 字节校验值本身不参与计算。
- 94 B payload 时共计算 100 字节。

### 2.2 16 位累加和（兼容校验）

部分固件不使用 CRC32，而是在帧尾 4 字节写 `[和低][和高][00][00]`，即对 `AA55 + ID + Length + Payload` 逐字节求和取低 16 位。

解析器在 CRC32 比对失败时会用累加和再比对一次，命中即视为校验通过。

### 2.3 默认行为

界面「CRC 校验」勾选框默认**不勾选**（`skipCrc = true`），此时不做校验，仅统计 `帧:N (CRC错:M)`。

## 3. 同 ID 长度分流（0x0166 / 内部 0x8166）

线上协议中「组合导航融合结果」与「倾斜测量」共用 ID `0x0166`，解析侧按 **payload 长度** 区分：

| 实际 ID | payload 长度 | 内部 ProtocolID | 名称 | 总帧长 |
|---|---|---|---|---|
| 0x0166 | 94（0x005E） | `FusionResult = 0x0166` | 组合导航（融合） | 104 B |
| 0x0166 | 105（0x0069） | `TiltMeasure = 0x8166`（内部区分值） | 倾斜测量 | 115 B |

分流函数：

```cpp
inline ProtocolID resolveProtocolID(uint16_t id, uint16_t len) {
    if (id == 0x0166) {
        if (len == 0x005E) return ProtocolID::FusionResult;
        if (len == 0x0069) return ProtocolID::TiltMeasure;
    }
    // ... 其它协议按 id 匹配
}
```

## 4. FusionResult：组合导航融合结果（payload 94 B）

### 4.1 字段定义表

偏移均为 **payload 内 0 基偏移**。

| 偏移 | 类型 | 字段 | 单位 / 缩放 | 说明 |
|---|---|---|---|---|
| 0 | uint32 | gpsWeekSecond | ms | GPS 周内秒（毫秒） |
| 4 | uint16 | gpsWeek | 周 | GPS 周计数 |
| 6 | int32 | lat | deg × 1e7 | 纬度，需除以 1e7 |
| 10 | int32 | lon | deg × 1e7 | 经度，需除以 1e7 |
| 14 | int32 | alt | mm | 高度，需除以 1000 得米 |
| 18 | float32 | velN | m/s | 北向速度 |
| 22 | float32 | velE | m/s | 东向速度 |
| 26 | float32 | velD | m/s | 地向速度 |
| 30 | float32 | roll | deg | 横滚角 |
| 34 | float32 | pitch | deg | 俯仰角 |
| 38 | float32 | yaw | deg | 航向角 |
| 42 | float32 | heading | deg | 航向（AHRS / RTK 双天线 / 前轮） |
| 46 | float32 | wheelAngle | deg | 前轮转角（G200 时有效） |
| 50 | float32 | accelX | g | 加速度计 X |
| 54 | float32 | accelY | g | 加速度计 Y |
| 58 | float32 | accelZ | g | 加速度计 Z |
| 62 | float32 | gyroX | deg/s | 陀螺仪 X |
| 66 | float32 | gyroY | deg/s | 陀螺仪 Y |
| 70 | float32 | gyroZ | deg/s | 陀螺仪 Z |
| 74 | float32 | temp | ℃ | IMU 温度 |
| 78 | uint8 | rtkStatus | — | 定位状态码，见 4.2 |
| 79 | uint8 | numSatellites | 颗 | 卫星数 |
| 80 | uint8 | diffAge | s | 差分龄期 |
| 81 | uint8 | dualAntStatus | — | 双天线状态，`50` = 已定向 |
| 82 | uint16 | posStd | cm | 位置标准差 |
| 84 | uint16 | statusFlag | 位域 | 状态标志，见 4.3 |
| 86 | uint32 | reserved1 | — | 预留 |
| 90 | uint32 | reserved2 | — | 预留 |

合计 94 字节。

### 4.2 rtkStatus 定位状态码

注意：0x0166 使用**简化定位质量码**，与 NAV_APPEND（0x0167）使用的 UM982 原始码（16/17/34/50）不同。

| 值 | 含义 |
|---|---|
| 0 | 未定位 |
| 1 | 单点 |
| 2 | 伪距差分 |
| 4 | 固定解 |
| 5 | 浮点解 |

### 4.3 statusFlag 状态标志位

| 位 | 掩码 | 含义 |
|---|---|---|
| bit0 | 0x0001 | RTK 有效 |
| bit1 | 0x0002 | PPS 有效 |
| bit2 | 0x0004 | 已初始化 |
| bit3 | 0x0008 | 前轮转角有效 |
| bit4 | 0x0010 | 已收敛 |
| bit5 | 0x0020 | 前轮陀螺有效 |
| bit6 | 0x0040 | 方向盘电机有效 |
| bit7~8 | — | 行驶方向：`1` = 前进，`2` = 后退 |

### 4.4 CSV 导出

CSV 表头（共 26 列）：

```text
GPS周秒(ms),周,纬度,经度,高度(m),VelN,VelE,VelD,Roll,Pitch,Yaw,Heading,Wheel,Ax,Ay,Az,Gx,Gy,Gz,Temp,RTK,Sat,DiffAge,DualAnt,PosStd(cm),Status
```

转换规则：

- 纬度 / 经度：原始值 ÷ 1e7，保留 7 位小数
- 高度：原始值 ÷ 1000，保留 3 位小数
- RTK：按 4.2 转中文名称
- DualAnt：`50` 输出「已定向」，其余输出原值
- Status：按 4.3 展开为中文标志串，如 `0x5[RTK有效,已初始化]`

### 4.5 数据分析侧映射

`convertFusionResult()` 把本帧转换为 `DataSet`：

- `lat = lat / 1e7`、`lon = lon / 1e7`、`height = alt / 1000.0`
- 速度、姿态、加计、陀螺、温度直接透传
- `fixType / numSatellites / diffAge / posStd / statusFlag` 一并带入

## 6. 解析流程

```text
原始字节流
  └─ findNextFrame      : 查找 AA 55 同步头
      └─ isFrameComplete: 读 Length，判断 6+Length+4 是否收齐
          └─ CRC 校验   : computeCrc32（失败再试 computeSum16）
              └─ resolveProtocolID(id, len)  : 0x0166 + 94/105 分流
                  └─ parsePayload
                      ├─ FusionResult → parseFusionResult(payload, f.fusion)
                      └─ TiltMeasure  → parseTiltMeasure(payload, f.tilt)
                          └─ 前进 6 + Length + 4 字节
```

`ParsedFrame` 中两者位于同一个 `union` 的不同成员：

```cpp
union {
    // ...
    FusionResult   fusion;
    TiltMeasure    tilt;
    // ...
};
```

因此**同一帧只能按其中一种解释**，判定依据就是 `resolveProtocolID` 的长度分流结果。

## 7. 实测备注（项目内部结论，非协议字段定义）

以下为项目联调/对比中已验证的行为，供数据分析时参考：

- 0x0166 输出的位置是**已补偿的投影点坐标**，不是原始天线相位中心位置。
- 速度**未做杆臂补偿**。
- 0x0166 与 CAN 原始天线位置（0x52 类数据）的高度差约等于垂直杆臂长度（实测约 0.45 m 量级，随安装变化）。
- 融合帧定位状态使用 0/1/2/4/5 简化码；若要 UM982 原始定位码（16/17/34/50），应改用 NAV_APPEND（0x0167）。

## 8. 扩展约定

新增同类 AA55 协议时：

1. 在 `protocoldefs.h` 增加 `ProtocolID` 枚举值、payload 结构体、`protocolName()` 分支和 `resolveProtocolID()` 映射。
2. 若与既有 ID 共用线协议 ID，必须在 `resolveProtocolID` 中**先按长度/内容分流**。
3. 在 `frameparser.cpp` 增加 `parseXxx(const uint8_t*, T&)`，全部使用 `readU16LE/readU32LE/readI32LE/readFloatLE/readDoubleLE` 等小端读取函数，并在 `parsePayload` 的 `switch` 中注册。
4. 在 `protocolregistry.cpp` 增加 `ProtocolDescriptor`：协议名、`ProtocolID`、是否默认校验 CRC、CSV 表头、解析 lambda、导出 lambda、字段描述列表（用于界面字段选择/表格展示）。
5. 若需要参与分析/绘图，在 `converter.h` 增加对应的 `convertXxx()` 并在 `convertToDataSet()` 中注册。

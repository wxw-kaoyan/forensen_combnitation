# 公共层（common）架构说明

## 1. 概述

`common/` 是 TASoftware 各模块共享的「非业务基础设施层」，不含任何具体业务逻辑，只提供三类能力：

| 类别 | 文件 | 职责 |
|------|------|------|
| 连接类 | `tcpconnection` / `serialconnection` / `pcanconnection` | TCP / 串口 / PCAN(CAN) 三种物理链路的统一收发封装 |
| 进程与 UI | `toolprocess` / `toolprocessmanager` / `uiinitializer` | 外部工具进程管理、主窗口尺寸与全局样式装配 |
| 第三方库 | `rtklib/` | RTKLIB 定位库源码，供 parse 模块 RTCM 深度解码、analysis 模块 RINEX 读取使用 |

在工程中的位置：

```
┌──────────────────────────────────────────────────────┐
│                 UI 层（mainwindow + 各模块面板）        │
└──────────────┬─────────────────────────┬─────────────┘
               │                         │
      ┌────────▼────────┐       ┌────────▼────────────┐
      │   modules/*     │       │  common/ 连接类       │
      │ commtool/ntrip  │──────▶│  TcpConnection       │
      │ ota/…           │       │  SerialConnection    │
      └─────────────────┘       │  PcanConnection      │
                                └────────┬────────────┘
               ┌────────────────────────┼──────────────┐
      ┌────────▼─────────┐    ┌─────────▼──────────┐   │
      │ ToolProcess(Manager) │  │ common/rtklib (.c) │   │
      │ UiInitializer        │  │ → parse / analysis │   │
      └──────────────────────┘  └────────────────────┘   │
```

```

    ├── rtkcmn.c / rtcm.c / rtcm3.c / rinex.c   # 参与编译的子集
    ├── rtcm_stubs.c            # 未用函数的空实现（避免拉入更多源文件）

```

## 3. 连接类三兄弟

三个连接类接口刻意保持同构：公共槽为「连接 / 断开 / 发送」，信号统一约定 `connected` / `disconnected` / `errorOccurred(QString)` / `logMessage(QString)`，均设计为**放入工作线程**使用。

| | TcpConnection | SerialConnection | PcanConnection |
|---|---|---|---|
| 底层 | `QTcpSocket` 直连 host:port | `QSerialPort` 参数化打开 | PCAN-Basic API（`QLibrary` 运行时加载 `PCANBasic.dll`） |
| 连接槽 | `connectToHost(host, port, timeoutMs=1000)` | `connectToPort(portName, baudRate, dataBits, parityIdx, stopBitsIdx, timeoutMs=1000)` | `connectToChannel(channelHandle, baudCode)` |
| 断开槽 | `disconnectFromHost()` | `disconnectFromPort()` | `disconnectFromChannel()` |
| 发送槽 | `send(QByteArray)` | `send(QByteArray)` | `send(id, data≤8字节, extended=false)` |
| 接收信号 | `dataReceived(QByteArray)` | `dataReceived(QByteArray)` | `frameReceived(id, data, msgType, timestampUs)`（结构化） |
| 收包机制 | `readyRead` → 写入缓冲；周期 10ms 定时器 flush 合并发射，≥4096 字节阈值立即发射兜底 | 同左 | 无回调 API，10ms 定时器轮询 `CAN_Read`，单次最多排空 128 帧 |
| 超时 | 单发 `QTimer`，默认 1000ms，超时发「连接超时（1秒）」并断开 | 同左 | 无（`CAN_Initialize` 同步返回） |

### 3.1 TcpConnection

`QTcpSocket` 直连 + 超时控制。几个防御细节：

- 超时定时器连接成功后即停表并 `deleteLater`；`cleanup()` 只断开 `errorOccurred` 连接再 `abort()`，防止关闭动作触发级联错误信号（注释指出 `waitForDisconnected` 在 Windows 可能挂死，故用 `abort()`）。
- `onSocketError()` 过滤 `UnknownSocketError`，避免无意义错误干扰连接流程。
- `disconnectFromHost()` 不显式 `emit disconnected`——`abort()` 后 `QTcpSocket::disconnected` 自然触发，避免双重发射。

**flush 合并发射机制**（SerialConnection 同构）：

连接期间 `m_flushTimer`（10ms 周期模式）始终运行，`readyRead` 只负责把新数据写入 `m_buffer`。定时器触发时 `flushBuffer()` 把当前缓冲一次性 `emit dataReceived`，随后 `clear()` + `squeeze()` 归还 capacity。额外保留 4096 字节阈值：单帧或短时间内连续到达的数据若累计 ≥4KB，立即 flush 不等定时器——这是极端高速率兜底（正常 1kHz×16ms ≈ 16 帧 ≈ 416B，永远碰不到）。

选择周期定时器而非 singleShot 的原因：**singleShot + readyRead 里 reset 的方案在高频数据流下永远触发不了定时器**（每次 readyRead 都重置计时），导致数据在缓冲里攒 3 秒才 flush 一次，接收区一顿一顿。改为周期模式后，Windows 默认时钟精度 ≈15.6ms（实际 flush 频率 ≈64Hz），匹配 60Hz 屏刷，接收区流畅。flushBuffer 用 DirectConnection 同步 emit，上层文件写入在 clear 之前完成，**不会丢数据**。

### 3.2 SerialConnection

参数化串口：数据位直转 `QSerialPort::DataBits`，校验位/停止位按下标映射静态表：

```cpp
static const QSerialPort::Parity kParityMap[] = {
    QSerialPort::NoParity, QSerialPort::EvenParity, QSerialPort::OddParity };
static const QSerialPort::StopBits kStopMap[] = {
    QSerialPort::OneStop, QSerialPort::OneAndHalfStop, QSerialPort::TwoStop };
```

以 `ReadWrite` 打开；失败则清理并 `errorOccurred("串口 %1 打开失败: %2")`。Windows 平台打开串口时常先收到一次 `NoError` 的 `errorOccurred`，已过滤。与 TCP 不同，`disconnectFromPort()` 会显式 `emit disconnected`。收包缓冲策略与 TcpConnection 完全一致（周期 10ms flush + 4096 字节阈值兜底）。

### 3.3 PcanConnection

对接 PEAK PCAN-Basic 4.x，**运行时 `QLibrary` 加载 `PCANBasic.dll`**（随 PEAK 驱动装在 System32），不链接导入库，规避 MinGW 与 MSVC 导入库格式不兼容问题。`loadApi()` 解析 `CAN_Initialize / CAN_Uninitialize / CAN_Read / CAN_Write / CAN_GetStatus / CAN_GetErrorText`，结果进程级共享一份（`Api g_api`）。

静态信息接口（供 UI 下拉框与状态栏使用）：

- `isDriverAvailable()`：DLL 能否加载（驱动是否安装）
- `availableChannels()`：即插即用通道，USB(0x51)/PCI(0x41)/PCC(0xC1)/LAN(0xE1) 各 16 个
- `availableBaudrates()`：BTR0BTR1 码表，1 Mbit/s(0x0014) ~ 5 kbit/s(0x7F7F) 共 10 档
- `statusText(status)`：状态码 → 中文描述，未知/组合码回退到 DLL 的 `CAN_GetErrorText`

轮询 `onPollTimer()`：读到 `PCAN_ERROR_QRCVEMPTY` 即收队；总线类错误（BUSLIGHT/BUSHEAVY/BUSWARNING）仅在状态变化时提示一次；溢出类只记日志；其余视为致命，报错并自动断开。时间戳按 `millis + 2^32 × millisOverflow` 还原绝对毫秒再并入微秒部分。结构体布局用 `static_assert(sizeof(PcanMsg)==16)`、`static_assert(sizeof(PcanTimestamp)==8)` 校验。

## 4. ToolProcess / ToolProcessManager

外部工具进程（如和芯解析 Converter、rtkplot）的启动与管理：查找 → 启动 → 状态同步 → 退出清理。

- `ToolProcess::Config`：`exeName` / `displayName` / 关联 `QPushButton` / 关联 `QLabel` / 可选 `arguments`。
- 工厂方法 `ToolProcess::create(cfg, parent)` 自动接线：按钮点击 → `launch()`；`started`/`stopped` → 按钮禁用/恢复、标签显示「运行中/未启动」并着色。
- `resolveExePath()`：先程序同目录（`applicationDirPath`），后备固定目录 `C:/Users/wxw/Desktop/QT/TASoftware`；两处都找不到弹窗报错。
- `terminate()`：`terminate()` + `waitForFinished(3000)`，仍不退则 `kill()`；析构时 `cleanupProcess()` 先断开全部信号再杀进程，防止析构期间触发 `stateChanged/finished`。

`ToolProcessManager` 进一步减负：`ToolSpec` 只填四个字符串（exe 名、显示名、按钮 objectName、标签 objectName），`registerTools()` 通过 `parent()->findChild()` 自动定位控件。构造函数默认注册两项：

```cpp
{"Converter3.0.7.exe", "和芯解析", "converterButton", "converterStatusLabel"},
{"rtkplot.exe",        "RTKPLOT",  "rtkplotButton",  "rtkplotStatusLabel"},
```

新增工具只需在这个列表加一行。

## 5. UiInitializer

无状态的静态工具类，`UiInitializer::apply(QMainWindow*)` 一次性完成：

- 窗口尺寸：按主屏可用区域取**屏宽 50% × 屏高 80%** 并居中，最小 900×600；取不到屏幕时回退最小 1280×840
- 状态栏初始消息 `Ready | UI prototype loaded`
- 全局 QSS：白底圆角卡片（headerFrame/ntripFrame/parseFrame 等 objectName）、深蓝按钮、Tab 页样式等

`mainwindow.cpp` 构造函数第一行即调用 `UiInitializer::apply(this)`。

## 6. rtklib/ 子目录

第三方 RTKLIB 2.4.2（patch p13）定位库源码原样 vendored。整个目录只有 **5 个 .c 参与编译**：`rtkcmn.c / rtcm.c / rtcm3.c / rtcm_stubs.c / rinex.c`，其余（`rcv/`、`ppp.c` 等）仅存档。`rtcm_stubs.c` 为未用到的 `decode_rtcm2` / `encode_rtcm3` 提供空实现，避免拉入更多源文件——本项目只需 RTCM 3.x 解码入口 `input_rtcm3()`。

编译方式（CMakeLists.txt）：

- Windows：MinGW 无可用 C 编译器场景下，5 个 .c 以 **C++ 方式编译**并加 `-Wno-write-strings` 抑制旧式 C 代码告警，同时定义 `WIN32` 宏
- Linux/ARM：启用 C 语言按 C 编译，无需特殊处理

两个消费方：parse 模块 `rtcm_deep_decoder.cpp` 逐字节喂 `input_rtcm3()` 做 RTCM 深度解码；analysis 模块 `rinexreader.cpp` 用 `readrnx()` 读取 RINEX 观测。

## 7. 线程模型与信号槽约定

连接类统一按「对象在工作线程、UI 在主线程」设计（头文件均注明「需放入工作线程」）：

1. 连接对象**无父对象**（或以 worker 为父）创建，随后 `moveToThread` 到工作线程
2. UI 跨线程调用槽用 `QMetaObject::invokeMethod(conn, &TcpConnection::connectToHost, Qt::QueuedConnection, ...)`，保证槽在工作线程执行
3. 连接对象的信号跨线程回到 UI 线程：`connected/disconnected/errorOccurred/logMessage/dataReceived` 全部按队列连接接收

例如 commtool 的用法：

```cpp
m_tcpConn = new TcpConnection;   // 无父对象，稍后移入线程
connect(m_tcpConn, &TcpConnection::dataReceived, this, [this](const QByteArray &data) { ... });
QMetaObject::invokeMethod(m_tcpConn, &TcpConnection::connectToHost,
                          Qt::QueuedConnection, host, port);
```

PcanConnection 因无回调 API、靠 10ms 定时器轮询收帧，同样依赖工作线程事件循环；单次最多排空 128 帧即让出，防止高总线负载占死线程。ToolProcess 则相反——QProcess 本身异步，直接在主线程使用。

## 8. 依赖关系

- **common 不反向依赖 modules**：common 下所有文件不 include 任何 `modules/` 头文件，依赖方向单一向上 ✔
- 被依赖情况（以实际 include 为准）：

| 消费方 | 使用 |
|--------|------|
| `mainwindow` | `ToolProcessManager`、`UiInitializer` |
| `modules/commtool` | `TcpConnection`、`SerialConnection` |
| `modules/ntrip`（ntripworker） | `TcpConnection` |
| `modules/ota`（otaworker） | `SerialConnection`、`TcpConnection` |
| `modules/parse`、`modules/analysis` | `common/rtklib`（`input_rtcm3` / `readrnx`） |
| `modules/simulator` | 无代码依赖（仅注释说明其 CRC 与 rtklib `rtk_crc32` 算法一致） |
| `PcanConnection` | 目前无模块消费，属预留能力 |

## 9. 扩展点

- **新增一种连接类型**（如蓝牙、UDP）：仿照三兄弟写一个 QObject 子类——公共槽 `connectXxx / disconnectXxx / send`，信号按数据形态选 `dataReceived(QByteArray)`（字节流）或 `frameReceived(...)`（结构化帧），外加 `connected / disconnected / errorOccurred / logMessage`；析构与断开走统一的 `cleanup()`（先断错误信号连接再关设备，防级联信号）；在头文件注明需放入工作线程。上层 UI 无需改动连接协议即可接入。
- **新增外部工具**：在 `ToolProcessManager` 构造函数的注册列表加一行 `{exe, 显示名, 按钮名, 标签名}`，并在 .ui 中放置对应 objectName 的按钮与标签。
- **扩展 RTKLIB**：如需更多 RTKLIB 功能，把对应 .c 加入 CMakeLists 的两处源文件列表（Windows 侧需同样设置 `LANGUAGE CXX` 与 `-Wno-write-strings`），并视情况删除 `rtcm_stubs.c` 中的同名 stub。

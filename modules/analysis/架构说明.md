# 分析模块（modules/analysis）架构说明

## 1. 概述

`modules/analysis` 是 TASoftware 的「数据分析」层，负责把已经解析好的数据（或原始观测文件）做质量检核、统计与可视化。它按功能划分为三个子模块：

| 子模块 | 目录 | 职责 |
|--------|------|------|
| 原始数据分析 | `raw/` | GNSS / IMU / 真值（GINS）三种原始数据的质量分析与曲线展示 |
| 对比分析 | `compare/` | 以真值文件为基准，与一个或多个对比文件做误差统计 |
| 核心工具 | `core/` | 统一数据模型、坐标/统计/时间对齐等无 UI 的纯工具函数 |

整体分层如下：

```
┌─────────────────────────────────────────────────────────┐
│                       UI 层（QWidget 面板）              │
│  RawAnalysisPanel（原始数据分析）  AnalysisPanel（对比）  │
└───────────────┬──────────────────────┬──────────────────┘
                │                      │
        ┌───────▼────────┐      ┌──────▼───────┐
        │  Reader 数据层  │      │  parse 模块   │
        │ RinexReader    │      │ columnextract │
        │ ImuReader      │      │ protocoldefs  │
        │ TruthReader    │      └──────────────┘
        └───────┬────────┘
        ┌───────▼─────────────────────────────┐
        │  core/ 核心工具（datamodel/mathutils…）│
        └─────────────────────────────────────┘
```

## 2. 目录结构

```
modules/analysis/
├── core/                      # 纯工具、无 UI
│   ├── datamodel.h            # DataPoint / DataSet / SceneSegment 统一数据模型
│   ├── mathutils.h            # 角度归一化、LLH→ENU 坐标转换
│   ├── statistics.h           # mean / rms / stdDev / percentile / 误差向量
│   ├── timealign.h            # 最近邻 / 精确时间戳对齐
│   └── converter.h            # ParsedFrame 列表 → DataSet 转换 + 摘要计算
├── raw/                       # 原始数据分析（含 UI）
│   ├── rawanalysispanel.h/.cpp # 原始数据分析主面板
│   ├── rinexreader.h/.cpp      # RINEX 观测文件质量统计
│   ├── imureader.h/.cpp        # IMU 原始 CSV 质量统计
│   └── truthreader.h/.cpp      # 真值文件（GINS 后处理输出）解析
└── compare/                   # 对比分析
    └── analysispanel.h/.cpp    # 真值 vs 对比文件误差统计面板
```

## 3. 核心数据模型（core/）

### 3.1 datamodel.h —— 统一数据点

`DataPoint` 是所有协议解析结果的「最大公约数」表示，覆盖位置、速度、姿态、IMU、质量指标五类字段，并用 `hasPosition/hasVelocity/hasAttitude/hasImu` 四个标志位表示字段是否有效。

`DataSet` 是 `DataPoint` 的集合，附带：

- 来源信息：`name`、`sourceType`、`sourcePath`
- 场景切段：`QVector<SceneSegment> scenes`
- 预计算摘要：起止时间、时长、平均数据率、丢点数、固定/浮点解帧数

内置两个按时间/场景筛选的辅助方法 `pointsInScene()` 与 `pointsInRange()`。

### 3.2 mathutils.h —— 坐标与角度

- `wrap180()`：角度归一化到 `[-180, 180]`
- `llh2diff()`：经纬高差分 → 北/东/天位移（米），基于 WGS84 长半轴 `RE_WGS84`
- `llh2enu()` / `batchLlh2enu()`：以参考点为原点的批量相对 ENU 坐标

### 3.3 statistics.h —— 统计工具

对标 MATLAB 的 `sigma_value / rms / std` 等：`mean`、`rms`、`stdDev`、`maxAbs`、`minVal`、`maxVal`、`percentile`（如 0.95 即 CEP95），以及 `horizontalError` / `error3D` 两类误差向量。

### 3.4 timealign.h —— 时间对齐

- `timeAlignNearest()`：按时间戳最近邻配对（容差 `toleranceMs`）
- `timeAlignExact()`：按时间戳精确匹配（`precisionMs`）

返回 `AlignedPair`，含对齐后的两路数据及匹配/跳过计数。

### 3.5 converter.h —— 协议帧 → DataSet

提供从解析层 `ParsedFrame` 列表到 `DataSet` 的转换：`convertAhRsBasic / convertAhRsExtended / convertQuaternion / convertAGData / convertFusionResult / convertTiltMeasure / convertAttitude / convertCanRtk`。

统一入口 `convert(frames, pid, typeName)` 按 `ProtocolID` 分发；`finalizeDataSet()` 做排序、去重、摘要与断点统计。

## 4. 原始数据分析（raw/）

### 4.1 数据类型多态

通过 `DataType` 枚举驱动三种数据类型：

```cpp
enum class DataType { Gnss = 0, Imu = 1, Truth = 2 };
```

三种 Reader 各自返回独立的摘要结构，由 `AnalyzeOutcome` 统一封装后在后台线程返回：

```cpp
struct AnalyzeOutcome {
    bool ok = false;
    DataType dataType;
    RinexSummary summary;   // GNSS
    ImuSummary imu;         // IMU
    TruthSummary truth;     // 真值
    QString err;
};
```

### 4.2 RinexReader —— GNSS 观测质量

复用 RTKLIB 的 `readrnx()` 读取原始观测量，输出 `RinexSummary`：

- 基本信息：观测记录总数、历元总数、时长、采样率（按中位数间隔）
- 系统/卫星：系统位掩码（GPS/GLO/GAL/QZS/BDS）、每系统卫星 PRN 集合、掉星集合
- 丢数检测：丢历元数、总间断时长（间隔 > 2×中位数）
- SNR：按系统×频点聚合的统计，以及每历元平均 SNR 时间序列

### 4.3 ImuReader —— IMU 原始数据质量

读取 New Code 导出的固定格式 CSV（时间 + 加计三轴 + 陀螺三轴）：

- 列名自动识别，单位自动识别（加计按模值中位数判断 g/m·s⁻²，陀螺按分位数判断 rad/s 或 °/s）
- 输出 `ImuSummary`：丢包检测、各轴 min/max/mean、加速度模值、角速度模值

### 4.4 TruthReader —— 真值解析

特点是真值文件头部元信息（英文旧版 / 中文新版）行数不固定、持续变化，因此**不按固定行数跳过**，而是：

1. 扫描定位「列名表头行」——同时包含 `Latitude` 与 `Longitude` 的行
2. 下一行为单位行（含括号），跳过
3. 再往下全部按空格分隔解析数据

列名归一化（转小写、去 `-`/`_`/空格）后按关键词匹配，支持 `latitude/lat`、`longitude/lon`、`hell/hgt`、`satuse` 等。输出 `TruthSummary` 含样本序列、位置范围、采样率等。

### 4.5 RawAnalysisPanel —— UI 与流程

界面结构：

- 左侧：数据类型 `QComboBox` + 树形导航 `QTreeWidget`（节点用 `Qt::UserRole` 存页面索引）
- 右侧：文件选择行 + `QStackedWidget` 内容堆栈（质量摘要 / 各类曲线页）

关键流程：

1. `onTypeChanged()` 切换 `DataType` → 清空结果 → 重建树
2. `onBrowse()` 按类型弹出对应文件过滤器的选择框
3. `onAnalyze()` 先 `resetResults()` 释放上次内存，再用 `QtConcurrent::run` 后台解析，避免 UI 阻塞
4. `onAnalyzeFinished()` 恢复控件、取结果，一次性构建该类型全部图表（切换树节点时直接显示，无需重建）

图表页用 `QSplitter(Qt::Vertical)` 包裹，支持拖拽调整图表高度；内容页索引与树节点一一对应。

### 4.6 图表交互

- `ZoomableChartView`：滚轮缩放 X 轴（时间轴），`Ctrl + 滚轮`缩放 Y 轴
- 横向 `QScrollBar` 平移时间轴，纵向 `QScrollBar` 平移 Y 轴（`attachTimeScrollBar` / `attachYScrollBar`）
- 高采样率数据（如 200 Hz）通过 `downSample()` 抽稀到 10 Hz 显示，降低绘制开销
- Heading 跨 0°/360° 时做 unwrap，避免曲线垂直跳变
- 真值位置/姿态三个子图垂直堆叠、共用底部时间轴，任一子图 `rangeChanged` 联动其他子图

## 5. 对比分析（compare/）

`AnalysisPanel` 以「真值文件」为基准，导入一个或多个对比文件：

- 使用 `parse/columnextract.h` 的 `TextFileTable` / `loadTextFileTable` 加载表格
- 手动指定时间列与「真值列 ↔ 对比文件列」的映射（`MetricMapping`）
- 时间戳**精确相等**才参与计算（`exactMatchTimes`）
- 按场景（手动截断时间）分别计算均值偏置 / RMS / 2σ

## 6. 线程模型

两个面板都采用「后台解析 + 异步回调」模式：

- `QtConcurrent::run` 在后台线程执行解析/统计
- `QFutureWatcher` 监听完成信号，回到 UI 线程更新界面
- 忙碌期间禁用相关控件（`setBusy` / 手动 `setEnabled`）

解析完成后所有图表一次性构建，切换页面只做 `QStackedWidget` 切换，避免重复计算。

## 7. 与 parse 模块的依赖

`analysis` 依赖 `parse` 模块提供的两类接口：

- `modules/parse/columnextract.h`：`TextFileTable`、`loadTextFileTable`（对比分析用）
- `modules/parse/parser/core/protocoldefs.h`：`ParsedFrame`、`ProtocolID`（converter.h 用）

即：`parse` 负责「协议/文本 → 结构化帧/表」，`analysis` 负责「结构化数据 → 质量统计与可视化」。

## 8. 扩展点

- **新增原始数据类型**：在 `DataType` 枚举加枚举值 → 新增对应 Reader（返回独立摘要）→ 在 `AnalyzeOutcome` 加字段 → 在 `RawAnalysisPanel` 的 `onTypeChanged / onBrowse / onAnalyze / onAnalyzeFinished / rebuildTree` 增加分支 → 增加对应图表构建方法。
- **新增协议帧转换**：在 `converter.h` 增加 `convertXxx` 并在 `convert()` 的 `switch` 中登记。
- **新增统计指标**：优先在 `core/statistics.h` 或 `core/mathutils.h` 增加纯函数，保持 UI 与算法解耦。

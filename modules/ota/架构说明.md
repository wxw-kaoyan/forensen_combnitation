# OTA 升级模块（modules/ota）架构说明

## 1. 概述

`modules/ota` 是 Witt.exe 的「OTA 升级」模块，负责把 `.firmware` 固件文件下发到设备 Bootloader，完成「进 BL → 同步 → 擦除 → 64B 分块烧写 → CRC 校验 → 重启」的完整流程，并通过进度条、阶段标签与日志向用户反馈。

串口流程移植自**量产版 C++ SDK**（`linux_uart_ota/C++`，已集成给客户的版本），协议帧与旧参照版一致，差别在**波特率不假定、AT 通道压制/恢复、进 BL 覆盖软复位窗口**等流程鲁棒性上（见 §4.3）。CAN 链路为**预留骨架**（见 §8）。

| 组件 | 文件 | 职责 |
|------|------|------|
| 协议层 | `core/otaprotocol.h/.cpp` | 帧格式定义、CRC32、组帧、AT 指令常量、文件名 CRC 提取（纯函数，无 UI 无连接） |
| 控制层 | `core/otaworker.h/.cpp` | 升级状态机 + ACK 解析 + 波特率探测 + CAN 预留接口，在工作线程内驱动整条链路 |
| UI 层 | `ui/otapanel.h/.cpp` | 链路/固件参数配置、开始/取消/读取版本、进度与日志展示 |

协议参照 Linux_UATR_OTA 工具：**下行帧头 `55 AA`、上行帧头 `AA 55`**，全小端。本模块独立，不依赖 `modules/parse`。

```
┌────────────────────────────────────────────────────────────┐
│                OtaPanel（QWidget，UI 线程）                  │
└───────────────┬────────────────────────────────────────────┘
                │ QThread + 跨线程信号槽（自动排队）
┌───────────────▼────────────────────────────────────────────┐
│   OtaWorker（工作线程：升级状态机 + ACK 解析 + 波特率探测）    │
├───────────────┬────────────────────────┬───────────────────┤
│ OtaProtocol    │ SerialConnection       │ PcanConnection    │
│ （组帧/CRC32）  │ （串口链路，已实现）      │ （CAN 链路，预留）  │
└───────────────┴────────────────────────┴───────────────────┘
```

## 3. 协议层（OtaProtocol）

### 3.1 帧格式

下行帧（主机 → 设备，帧头 `55 AA`）共三种：

- `buildLongCmd(cmd)`：**34 字节** `sync(2)+id(2)+len(2)+params(24 全 0)+crc(4)`，len 固定 24（6×u32）；用于 GET_SYNC / CHIP_ERASE / GET_CRC / REBOOT 等无参命令。
- `buildDataFrame(offset, size, data)`：**81 字节** `sync(2)+id(2)+len(2)+data[64]+offset(4)+size(2)+cmd(1)+crc(4)`，len 固定 71，id 固定 `PROG_MULTI`，cmd 子命令填 0；数据区不足 64 字节补零。
- `buildEnterBootCmd()`：**34 字节**进 Bootloader 固定帧（id=`0x88BB`），字节内容与量产版 SDK 的 `kEnterBootCmd` 逐字节一致。

上行帧（设备 → 主机，帧头 `AA 55`）由 `OtaWorker` 的 ACK 状态机逐字节解析（见 4.2）。

### 3.2 指令集与 AT 指令

| 命令字 | 值 | 含义 |
|--------|------|------|
| `GET_SYNC` / `GET_DEVICE` / `CHIP_ERASE` / `CHIP_VERIFY` | 0x21/0x22/0x23/0x24 | 握手 / 读设备信息 / 擦除 APP 区 / 校验（流程中校验实际走 `GET_CRC`） |
| `PROG_MULTI` / `GET_CRC` / `REBOOT` | 0x27/0x29/0x30 | 64B 块烧写 / 芯片回算固件 CRC32 / 重启 |
| `RESET_MAGIC` | 0x88BB | 进 Bootloader 指令帧的 id |
| `ACK_CMD` / `ACK_CRC` / `ACK_OFFSET` | 0x0064/0x753C/0x753D | 上行应答：命令应答 / 芯片侧 CRC / 已确认 offset |
| `OK` | 0x10 | `ACK_CMD` 中 command==0x10 视为成功 |

文本指令（进 BL 前后用于压停 / 恢复设备主动输出、读版本）：

| 常量 | 内容 | 用途 |
|------|------|------|
| `kCmdSetNo` | `AT+SETNO\r\n` | 让设备停止主动输出，避免升级指令被数据流淹没 |
| `kCmdSetYes` | `AT+SETYES\r\n` | 升级收尾恢复设备主动输出（连发 3 次） |
| `kCmdVersion` | `AT+VERSION\r\n` | 读版本，应答原样返回不解析 |
| `kCmdStay` | `HC32MCU_FORSENSE` | Bootloader 停留指令（进 BL 后盲发覆盖软复位窗口） |

### 3.3 校验

- `crc32()`：IEEE 802.3 表驱动 CRC32，**初值 = 1**，覆盖 sync~payload（不含 CRC 本身）。
- `crc32File()`：按 64KB 分块计算整个固件文件 CRC，失败返回 0 并填 err。
- 固件文件名须含 `#CRC<十进制>`，`extractCrcFromFileName()` 提取作为升级后校验的期望值。
- `kBlockSize=64`；`kBootBaud=115200` 仅为**探测失败时的兜底值**，正常按探测结果（见 4.3）。

## 4. 控制层（OtaWorker）

### 4.1 配置与阶段

```cpp
enum class Transport { Serial, Can };
enum class Phase { Idle, Connecting, Resetting, Handshaking, Erasing,
                   Programming, Verifying, Rebooting, Done, Failed };
struct Config {
    Transport transport = Transport::Serial;

    QString port;
    int     appBaud  = 0;      // APP 当前波特率；0 = 自动探测（依次试候选波特率）
    bool    autoReset = true;  // true=发进BL指令自动进 BL；false=设备已手动进 BL

    int      canChannel  = 0;  // PcanConnection::availableChannels() 的 handle
    int      canBaudCode = 0;  // PcanConnection::availableBaudrates() 的 code
    uint32_t canTxId     = 0;  // 下发报文 ID（待协议文档）
    uint32_t canRxId     = 0;  // 上收报文 ID（待协议文档）
    bool     canExtended = false;

    QString firmwarePath;
    bool    versionOnly = false;  // 只读版本不擦写（UI「读取版本」）
};
```

对外信号：`phaseChanged(Phase, QString)`、`progress(int percent)`、`logMessage(QString)`、`versionRead(QString)`、`finished(bool success, QString summary)`。

### 4.2 ACK 接收状态机

`feedRxByte()` 实现逐字节状态机 `WaitSync1 → WaitSync2 → WaitId1/2 → WaitLen1/2 → Payload → WaitCrc1..4`，边收边累积 CRC（初值 1）。CRC 匹配且 payload ≥ 8 字节时按 id 分发：

- `ACK_CMD`：word0 == `OK`(0x10) → 置 `m_ackOk`
- `ACK_CRC`：word1 → `m_crcAck`（芯片侧固件 CRC32）
- `ACK_OFFSET`：word1 → `m_offsetAck`（已确认烧写 offset）

同一份字节流同时进入 `m_rawBuf`，供 AT 应答读取与「串口静默」判定使用（`readQuiet()`：收到数据后静默 `kQuietBreakMs`=100ms 即认为读完整）。

### 4.3 串口升级流程（`start()` → `runSerialUpgrade()`，worker 线程内）

流程常量集中在 `otaworker.cpp` 匿名命名空间：候选波特率 `{9600,115200,230400,460800,921600}`；进 BL 后盲发 `×40`（50ms）；擦除 ACK 30s；单块重发上限 **5** 次、offset ACK 1s；「擦除→烧写→校验」整轮重试 3 轮（**仅 CRC 不一致才重试**）。

1. **固件预检**（纯本地，先于进入 BL，避免固件不合法时把设备留在 Bootloader）：文件名缺 `#CRC` → fail；大小非 4 的倍数 → fail；扩展名非 `.firmware` 仅提示；本地 `crc32File()` 与文件名 CRC 交叉比对并打日志（不一致打警告但不中止）。
2. **连接**：`openTransport(baud)` → `SerialConnection::connectToPort(port, baud, 8, 0, 0, 8s)`；波特率 `appBaud==0` 时先以 9600 打开再由探测流程热切换。
3. **读升级前版本 + 定位波特率**（`readVersionInternal()`）：自动模式下 `detectAppBaud()` 依次试候选波特率，每个波特率先 `atPrepareChannel()`（连发 `AT+SETNO` 直到串口安静或 10s 超时，把设备的 `OK` 应答识别为「已安静」而非「还在输出」）再发 `AT+VERSION`，应答含 `+VERSION` 才算命中 APP；全部失败则 `scanBlBaud()` 逐波特率试同步，命中则判定设备**已在 Bootloader**。已知波特率时直接 `AT+SETNO` + `AT+VERSION`。
4. **进 BL**（`enterBootloader()`）：`autoReset` 时以 APP 波特率发进 BL 固定帧 ×3 → `drainTx(500)` + 睡 100ms（防止切波特率时字节卡在半途）；随后 `scanBlBaud()` 探测 **Bootloader 波特率**（不再假定 115200），命中后**盲发停留指令 ×40（50ms 间隔）覆盖软复位窗口**再 `doSync()`。未命中则兜底切 115200 盲发 ×40 + 最多 20 轮等同步（期间可手动断电再上电）。手动模式跳过进 BL 指令，直接探测 + 同步，并对已知 APP 波特率场景在 `AT+SETNO` 未压停数据流时直接判失败。
5. **擦除→烧写→校验**（最多 3 轮）：
   - `eraseChip()`：发 `CHIP_ERASE`，睡 2s 后等 ACK 30s（失败直接停止，不进入下一轮）；
   - `programFirmware()`：按 **64B/块** 组 `PROG_MULTI` 数据帧下发，等 offset ACK 等于当前块偏移（1s），未确认则 `doSync()` 重同步后重发，**单块上限 5 次**；每块成功后按已发字节发 `progress` 百分比；
   - `verifyCrc()`：发 `GET_CRC` ×10 → 睡 1s → 等 `ACK_CRC` 1s → 比较芯片 CRC 与文件名期望 CRC，返回 `Ok / Mismatch / NoAck`；只有 `Mismatch` 才整轮重试。
6. **重启与收尾**：CRC 通过后**无条件**发 `REBOOT` ×10 → 睡 3s → 若 APP 波特率未知则 `probeAppBaudOnly()` 重探 → 重读版本（失败仅警告，**升级成功与否以 CRC 为准**）→ 发 `AT+SETYES` ×3 恢复设备主动输出 → `progress(100)` → `Phase::Done` → `finished(true)`。

「读取版本」按钮走 `runReadVersionOnly()`：同一套连接与探测逻辑，只读版本、不擦写，结束即关闭链路。

任何阶段失败统一走 `fail()`：`Phase::Failed` + 日志 + `closeTransport()` + `finished(false)`。

## 5. UI 层（OtaPanel）

界面自上而下：链路设置（串口/CAN 切换）→ 固件选择 → 自动进 BL 勾选（默认勾选）→ 开始升级 / 读取版本 / 取消 → 版本显示 → 进度条 → 阶段标签 → 只读日志。

- `refreshPorts()`：枚举 `QSerialPortInfo::availablePorts`，`itemData` 存 portName；无串口时填「无可用串口」占位项。
- 串口行：串口下拉 + 刷新 + **APP 波特率（可编辑，默认「0（自动探测）」）**；填 0 或非数字时 `appBaud=0`，两种波特率都交由 worker 自动定位。
- CAN 行：通道下拉（`PcanConnection::availableChannels()`）、波特率下拉（`availableBaudrates()`）、下发/上收 ID（十六进制，可留空）；驱动不可用时提示「PCAN 驱动不可用」。
- `onBrowseFirmware()` / `updateFirmwareInfo()`：过滤器 `固件文件 (*.firmware);;所有文件 (*)`，显示大小、文件名 CRC、本地 CRC 及「✓一致 / ✗不一致」（`OtaPanel` 直接使用 `OtaProtocol` 做预检）。
- `startWorker(versionOnly)`：校验链路参数后组装 `Config`；`new QThread` + `new OtaWorker` → `moveToThread` → `thread.started` 触发 `start()`；`setRunning(true)` 禁用配置控件、启用取消按钮。CAN 链路仅作配置校验，读取版本按钮只在串口链路可用。
- `onCancel()`：`QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 调 `cancel()`，并禁用取消按钮防止重复请求。
- `onFinished()`：恢复控件，按成败弹 `QMessageBox` 并写日志；worker/thread 通过 `finished → thread.quit → deleteLater` 自清理。
- 析构兜底：cancel → `quit()` → `wait(3000)`。

## 6. 线程模型与取消语义

- **线程归属**：`OtaWorker` 及其在 `openTransport()` 内创建的 `SerialConnection`/`PcanConnection`（以 worker 为 parent）全部活在工作线程；worker 的信号跨线程自动排队送达 UI。
- **取消**：`m_cancel` 为 `std::atomic<bool>`；工作线程在 `waitEvent()`（QEventLoop + 50ms tick 定时器轮询 m_cancel/条件）与 `sleepMs()`（20ms 步进检查）中及时响应；每个探测候选波特率、每个升级轮次、每个 64B 块、每次重发前都检查 `m_cancel`，取消后统一走 `fail(QStringLiteral("已取消"))`，保证链路关闭与 `finished(false)` 必定发出。
- **单实例**：`m_worker` 非空时 `startWorker()` 直接返回，一次只允许一个升级任务。

## 7. 与 common 模块的依赖

依赖方向：`ui/otapanel` → `core/otaworker` → `common/serialconnection`、`common/pcanconnection`。

- 串口链路走 `SerialConnection::connectToPort/send/setBaudRate/drainTx`；其中 `setBaudRate()` 为本次新增的**已打开状态热切换波特率**能力（波特率探测需要），`drainTx()` 用于切波特率前排空发送缓冲。
- CAN 链路走 `PcanConnection::connectToChannel/send` + `frameReceived`，与串口链路信号语义一致，`OtaWorker` 用 `tx()` 屏蔽差异。
- 串口被其他进程占用时 `SerialConnection` 会把 `PermissionError` 映射为「串口 X 被其他进程占用…」提示，`OtaWorker::waitConnected()` 检测到该错误立即失败，不再干等满超时。

## 8. 扩展点

- **实现 CAN 升级流程**：只需填充 `OtaWorker::canEnterBoot/canSyncBoot/canErase/canProgram/canVerifyCrc/canReboot` 六个步骤（当前均返回 false 并打「预留接口」日志）与 `canSend()` 的报文切分规则；`runCanUpgrade()` 的阶段切换、进度、日志、取消、链路接线已就绪，上层无需改动。
- **适配新固件协议版本**：命令字与 AT 指令集中在 `OtaProtocol`；帧长/字段变化改 `buildLongCmd()/buildDataFrame()/buildEnterBootCmd()`；上行 ACK 语义变化在 `OtaWorker::feedRxByte()` 的 ACK 分支登记。
- **调整重试节奏/探测候选**：`otaworker.cpp` 匿名命名空间的 `kBaudCandidates`/`kBlockRetryMax`/`kUpgradeRounds`/`kForsenseWindowCount`/`kEraseAckWaitMs` 等常量集中一处，改值不动流程代码。
- **新增传输链路**：`Transport` 枚举加值 → `openTransport()/tx()/closeTransport()` 加分支 → `OtaPanel` 链路下拉框加项（itemData 存枚举值）。

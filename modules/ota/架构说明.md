# OTA 升级模块（modules/ota）架构说明

## 1. 概述

`modules/ota` 是 Witt.exe 的「OTA 升级」模块，负责把固件文件下发到设备 Bootloader，完成「进 BL → 同步 → 擦除 → 分块烧写 → 校验 → 重启」的完整流程，并通过进度条、阶段标签与日志向用户反馈。

当前支持**两种升级协议**、**两种传输链路**：

| 维度 | 取值 | 状态 |
|------|------|------|
| 协议 | 原极（`55 AA` 帧，`.firmware`） | 已实现 |
| 协议 | 元鼎 X50 子设备 YModem（`.bin`） | 已实现 |
| 链路 | 串口（`SerialConnection`） | 已实现 |
| 链路 | CAN（`PcanConnection`） | **预留骨架**，报文格式待协议文档 |

原极串口流程移植自**量产版 C++ SDK**（`linux_uart_ota/C++`），帧格式与旧参照版一致，差别在**波特率不假定、AT 通道压制/恢复、进 BL 覆盖软复位窗口**等流程鲁棒性上（见 §5.3）。

| 组件 | 文件 | 职责 |
|------|------|------|
| 协议层 | `core/otaprotocol.h/.cpp` | `OtaProtocol`（55 AA 帧 + CRC32）与 `YModemOta`（YModem 组帧 + CRC16）两个命名空间，纯函数，无 UI 无连接 |
| 控制层 | `core/otaworker.h/.cpp` | 升级状态机 + ACK 解析 + 波特率探测 + YModem 收发 + CAN 预留接口，在工作线程内驱动整条链路 |
| UI 层 | `ui/otapanel.h/.cpp` | 链路/协议/固件参数配置、开始/取消/读取版本、进度与日志展示 |

本模块独立，不依赖 `modules/parse`。

```
┌────────────────────────────────────────────────────────────┐
│                OtaPanel（QWidget，UI 线程）                  │
└───────────────┬────────────────────────────────────────────┘
                │ QThread + 跨线程信号槽（自动排队）
┌───────────────▼────────────────────────────────────────────┐
│   OtaWorker（工作线程：升级状态机 + 波特率探测 + YModem）      │
├───────────────┬────────────────────────┬───────────────────┤
│ OtaProtocol    │ SerialConnection       │ PcanConnection    │
│ YModemOta      │ （串口链路，已实现）      │ （CAN 链路，预留）  │
└───────────────┴────────────────────────┴───────────────────┘
```

## 3. 协议层（otaprotocol）

### 3.1 原极协议（`namespace OtaProtocol`）

下行帧头 `55 AA`、上行帧头 `AA 55`，全小端，共三种下行帧：

- `buildLongCmd(cmd)`：**34 字节** `sync(2)+id(2)+len(2)+params(24 全 0)+crc(4)`，len 固定 24（6×u32）；用于 GET_SYNC / CHIP_ERASE / GET_CRC / REBOOT 等无参命令。
- `buildDataFrame(offset, size, data)`：**81 字节** `sync(2)+id(2)+len(2)+data[64]+offset(4)+size(2)+cmd(1)+crc(4)`，len 固定 71，id 固定 `PROG_MULTI`，cmd 子命令填 0；数据区不足 64 字节补零。
- `buildEnterBootCmd()`：**34 字节**进 Bootloader 固定帧（id=`0x88BB`），字节内容与量产版 SDK 的 `kEnterBootCmd` 逐字节一致。

上行帧由 `OtaWorker` 的 ACK 状态机逐字节解析（见 §4.2）。

| 命令字 | 值 | 含义 |
|--------|------|------|
| `GET_SYNC` / `GET_DEVICE` / `CHIP_ERASE` / `CHIP_VERIFY` | 0x21/0x22/0x23/0x24 | 握手 / 读设备信息 / 擦除 APP 区 / 校验（流程中校验实际走 `GET_CRC`） |
| `PROG_MULTI` / `GET_CRC` / `REBOOT` | 0x27/0x29/0x30 | 64B 块烧写 / 芯片回算固件 CRC32 / 重启 |
| `RESET_MAGIC` | 0x88BB | 进 Bootloader 指令帧的 id |
| `ACK_CMD` / `ACK_CRC` / `ACK_OFFSET` | 0x0064/0x753C/0x753D | 上行应答：命令应答 / 芯片侧 CRC / 已确认 offset |
| `OK` | 0x10 | `ACK_CMD` 中 command==0x10 视为成功 |

AT / 文本指令（进 BL 前后压停、恢复设备主动输出，读版本）：

| 常量 | 内容 | 用途 |
|------|------|------|
| `kCmdSetNo` | `AT+SETNO\r\n` | 让设备停止主动输出，避免升级指令被数据流淹没 |
| `kCmdSetYes` | `AT+SETYES\r\n` | 升级收尾恢复设备主动输出（连发 3 次） |
| `kCmdVersion` | `AT+VERSION\r\n` | 读版本，应答原样返回不解析 |
| `kCmdStay` | `HC32MCU_FORSENSE` | Bootloader 停留指令（进 BL 后盲发覆盖软复位窗口） |

校验：`crc32()` 为 IEEE 802.3 表驱动，**初值 = 1**，覆盖 sync~payload；`crc32File()` 按 64KB 分块算整个固件；文件名须含 `#CRC<十进制>`，由 `extractCrcFromFileName()` 提取作为升级后的期望值。`kBlockSize=64`；`kBootBaud=115200` 仅为**探测失败时的兜底值**。

### 3.2 元鼎 YModem 协议（`namespace YModemOta`）

依据《X50子设备YModem_OTA升级协议V1.0》，与原极 `55 AA` 完全独立：

| 步骤 | 帧内容 |
|------|--------|
| 进 OTA | `FF FF 01 00 00 00 00 FF`（8 字节，前 7 字节累加和取低 8 位），设备回 `'C'`(0x43) |
| 版本查询 | `FF FF 74 00 00 00 00 72`，回复 `FF 00 84 ... 版本字节1 版本字节2 校验和` |
| 文件信息块 | `SOH 00 FF` + `"文件名\0固件长度(ASCII)\0"` 补零至 128B + CRC16（**高字节先发**） |
| 数据块 | `STX`(1024) 或 `SOH`(128) ｜ 块号 ｜ `~块号` ｜ 数据（补零） ｜ CRC16 |
| 结束 | `EOT`(0x04) → ACK，再发 `SOH` 全零结束块 → ACK（超时仍视为完成） |

块校验为 **CRC-16/CCITT-FALSE**（poly `0x1021`，初值 0，不反转、不异或），由 `crc16Ccitt()` 实现。

版本解析 `parseVersionReply(raw, ok, byte1, byte2)`：

- 在线版本值 = `版本字节1 × 10 + 版本字节2`；
- **`byte1/byte2` 必须用出参返回原始字节**，显示时不能从合成值反推（编码不可逆，例：`FF 00 84 00 02 11 19 AF` → 字节 `0x11/0x19`，版本 `V0.17.25`，数值 195）。

## 4. 控制层（OtaWorker）

### 4.1 配置与阶段

```cpp
enum class Transport { Serial, Can };
enum class Protocol  { YuanJi, YuanDing };
enum class Phase { Idle, Connecting, Resetting, Handshaking, Erasing,
                   Programming, Verifying, Rebooting, Done, Failed };

struct Config {
    Transport transport = Transport::Serial;
    Protocol  protocol  = Protocol::YuanJi;

    QString port;              // 串口
    int     appBaud  = 0;      // 0 = 自动探测（依次试候选波特率）
    bool    autoReset = true;  // true=发进BL指令自动进 BL；false=设备已手动进 BL

    QString firmwarePath;
    bool    allowNoNameCrc  = true;   // 原极：允许文件名无 #CRC（此时跳过 CRC32 校验）
    int     ymodemBlockSize = YModemOta::kBlock1024;  // 元鼎：1024(STX)/128(SOH)

    int      canChannel = 0, canBaudCode = 0;
    uint32_t canTxId = 0, canRxId = 0;
    bool     canExtended = false;

    bool    versionOnly = false;  // 只读版本不擦写（UI「读取版本」）
};
```

对外信号：`phaseChanged(Phase, QString)`、`progress(int)`、`logMessage(QString)`、`versionRead(QString)`、`finished(bool, QString)`。

`start()` 按配置分派：

```
protocol==YuanDing && transport==Serial  → m_ymMode=true
    ├─ versionOnly → runYmodemReadVersion()
    └─ 否则        → runYmodemUpgrade()
versionOnly            → runReadVersionOnly()
transport==Can         → runCanUpgrade()      // 骨架
否则                   → runSerialUpgrade()
```

每个流程入口统一调用 `resetSession(defaultBaud)` 复位会话状态（波特率、探测标志、原始缓冲、版本缓冲），避免复用 worker 时残留脏状态。

### 4.2 ACK 接收状态机（原极）

`feedRxByte()` 逐字节状态机 `WaitSync1 → WaitSync2 → WaitId1/2 → WaitLen1/2 → Payload → WaitCrc1..4`，边收边累积 CRC（初值 1）。CRC 匹配且 payload ≥ 8 字节时按 id 分发：

- `ACK_CMD`：word0 == `OK`(0x10) → 置 `m_ackOk`
- `ACK_CRC`：word1 → `m_crcAck`
- `ACK_OFFSET`：word1 → `m_offsetAck`

同一份字节流同时进入 `m_rawBuf`，供 AT 应答读取与「串口静默」判定（`readQuiet()`：收到数据后静默 `kQuietBreakMs`=100ms 即认为读完整）。

**元鼎 YModem 模式（`m_ymMode`）下不喂该状态机**：上行只有 `ACK/NAK/'C'` 单字节，由 `ymWaitByte()` 直接在 `m_rawBuf` 里匹配。

### 4.3 原极串口升级流程（`runSerialUpgrade()`）

流程常量集中在 `otaworker.cpp` 匿名命名空间：候选波特率 `{9600,115200,230400,460800,921600}`；进 BL 后盲发 `×40`（50ms）；擦除 ACK 30s；单块重发上限 **5** 次、offset ACK 1s；整轮重试 3 轮（**仅 CRC 不一致才重试**）。

1. **固件预检**（纯本地，先于进入 BL，避免固件不合法时把设备留在 Bootloader）：文件名缺 `#CRC` 且未允许 → fail；大小非 4 的倍数 → fail；扩展名非 `.firmware` 仅提示；本地 CRC 与文件名 CRC 交叉比对并打日志（不一致只警告）。
2. **连接**：`openTransport(baud)` → `SerialConnection::connectToPort(port, baud, 8, 0, 0, 8s)`；`appBaud==0` 时先以 9600 打开再由探测热切换。
3. **[1/5] 读升级前版本 + 定位波特率**（`readVersionInternal()`）：自动模式下 `detectAppBaud()` 逐档试 `atPrepareChannel()` + `AT+VERSION`，应答含 `+VERSION` 才算命中 APP；全部失败则 `scanBlBaud()` 逐档试同步，命中即判定设备**已在 Bootloader**。已知波特率时直接 `AT+SETNO` + `AT+VERSION`。
4. **进 BL 并同步**（`enterBootloader()`）：`autoReset` 时以 APP 波特率发进 BL 固定帧 ×3 → `drainTx(500)` + 睡 100ms（防切波特率时字节卡在半途）；随后 `scanBlBaud()` 探测 **Bootloader 波特率**（不假定 115200），命中后**盲发停留指令 ×40（50ms）覆盖软复位窗口**再 `doSync()`。未命中则兜底切 115200 盲发 ×40 + 最多 20 轮等同步（期间可手动断电再上电）。手动模式跳过进 BL 指令。
5. **[2/5]~[4/5] 擦除 → 烧写 → 校验**（最多 3 轮）：
   - `eraseChip()`：发 `CHIP_ERASE`，睡 2s 后等 ACK 30s（失败直接停止）；
   - `programFirmware()`：按 **64B/块** 下发 `PROG_MULTI`，等 offset ACK 等于当前块偏移（1s），未确认则 `doSync()` 重同步后重发，**单块上限 5 次**；每块更新 `progress`；
   - `verifyCrc()`：发 `GET_CRC` ×10 → 睡 1s → 等 `ACK_CRC` 1s → 比对，返回 `Ok / Mismatch / NoAck`；只有 `Mismatch` 才整轮重试。
6. **[5/5] 重启与收尾**：CRC 通过后**无条件**发 `REBOOT` ×10 → 睡 3s → APP 波特率未知则 `probeAppBaudOnly()` 重探 → 重读版本（失败仅警告，**成功与否以 CRC 为准**）→ `AT+SETYES` ×3 恢复主动输出 → `progress(100)` → `Phase::Done` → `finished(true)`。

### 4.4 元鼎 YModem 升级流程（`runYmodemUpgrade()`）

YModem 常量：`kYmCHandshakeMs=10000`、`kYmBlock0AckMs=5000`、`kYmShortCMs=500`、`kYmDataAckMs=10000`、`kYmEotAckMs=10000`、`kYmRetryMax=3`、`kYmRoundMax=2`。

1. **固件预检**：只要求文件非空；Block0 自行声明长度，**不要求 `#CRC`，也不要求 4 字节对齐**；文件名取 `completeBaseName()`（不带扩展名）。
2. **连接**：自动模式以 115200 打开，再逐档探测。
3. **版本查询**（`ymDetectBaud()` / `ymReadVersion()`）：连发 3 次版本查询帧，收数据后静默 100ms 判完整；读不到只警告，不阻断升级。
4. **进入 OTA**（`ymEnterOta()`）：发 `FF FF 01...`，等 `'C'`；单轮重发 3 次，整体 2 轮。
5. **Block0 → 数据块 → EOT → 结束块**：`ymSendFileInfo()` / `ymSendData()` / `ymSendEot()` / `ymSendEndBlock()`，每步最多重发 3 次（NAK 或超时都重发）。
6. 发送完毕即 `progress(100)`、等 500ms 后关闭链路；设备自行校验并重启。

### 4.5 只读版本

- 原极：`runReadVersionOnly()`，同一套连接与探测逻辑，只读版本、不擦写。
- 元鼎：`runYmodemReadVersion()`，只发版本查询帧。

### 4.6 失败与取消

任何阶段失败统一走 `fail()`：`Phase::Failed` + 日志 + `closeTransport()` + `finished(false)`。

## 5. UI 层（OtaPanel）

界面自上而下：链路设置（串口/CAN）→ 固件（协议 / YModem 块大小 / 文件名 CRC 选项 / 文件选择）→ 自动进 BL 勾选 → 开始升级 / 读取版本 / 取消 → 版本显示 → 进度条 → 阶段标签 → 只读日志。

- `refreshPorts()`：枚举 `QSerialPortInfo::availablePorts()`，`itemData` 存 portName；无串口时填「无可用串口」占位项。
- 串口行：串口下拉 + 刷新 + **APP 波特率（可编辑，默认「0（自动探测）」）**。
- CAN 行：通道/波特率下拉（`PcanConnection::availableChannels()/availableBaudrates()`）、下发/上收 ID（十六进制）；驱动不可用时提示「PCAN 驱动不可用」。
- 协议下拉：`原极 OTA（55 AA 帧）` / `元鼎 YModem OTA`。切到元鼎时：
  - 启用「YModem 块大小」下拉（1024 STX / 128 SOH）；
  - 禁用「自动进 BL」（YModem 由设备回 `'C'` 握手）；
  - 禁用「固件文件名可无 #CRC」（YModem 不需要 #CRC）。
- `updateFirmwareInfo()`：显示大小、文件名 CRC、本地 CRC 及「✓一致 / ✗不一致」。
- `startWorker(versionOnly)`：校验参数后组装 `Config`；元鼎协议强制串口链路；`new QThread` + `new OtaWorker` → `moveToThread` → `thread.started` 触发 `start()`；`setRunning(true)` 禁用配置控件、启用取消按钮。
- `onFinished()`：恢复控件，按成败弹 `QMessageBox` 并写日志；worker/thread 通过 `finished → thread.quit → deleteLater` 自清理。
- 析构兜底：cancel → `quit()` → `wait(3000)`。

## 6. 线程模型与取消语义

- **线程归属**：`OtaWorker` 及其在 `openTransport()` 内创建的 `SerialConnection`/`PcanConnection`（以 worker 为 parent）全部活在工作线程；worker 信号跨线程自动排队送达 UI。
- **取消**：`m_cancel` 为 `std::atomic<bool>`；`waitEvent()`（QEventLoop + 50ms tick 轮询 m_cancel/条件）与 `sleepMs()`（20ms 步进检查）中及时响应；每个探测档位、每个升级轮次、每个数据块、每次重发前都检查，取消后统一走 `fail("已取消")`。
- **单实例**：`m_worker` 非空时 `startWorker()` 直接返回。

## 7. 与 common 模块的依赖

依赖方向：`ui/otapanel` → `core/otaworker` → `common/serialconnection`、`common/pcanconnection`。

- 串口走 `SerialConnection::connectToPort/send/setBaudRate/drainTx`；`setBaudRate()` 支持**打开状态下热切换**（波特率探测需要），`drainTx()` 用于切档前排空发送缓冲。
- CAN 走 `PcanConnection::connectToChannel/send` + `frameReceived`，`OtaWorker::tx()` 屏蔽链路差异。
- 串口被占用时 `SerialConnection` 把 `PermissionError` 映射为中文提示，`waitConnected()` 检测到错误立即失败，不干等满超时。

## 8. 扩展点

- **实现 CAN 升级流程**：填充 `canEnterBoot/canSyncBoot/canErase/canProgram/canVerifyCrc/canReboot` 六个步骤（当前均返回 false 并打「预留接口」日志）与 `canSend()` 的切分/流控规则；`runCanUpgrade()` 的阶段切换、进度、日志、取消、接线已就绪。
- **新增升级协议**：`Protocol` 枚举加值 → `start()` 分派加分支 → 在 `otaprotocol` 加同名命名空间实现组帧/解析 → `OtaPanel` 协议下拉加项（itemData 存枚举值）。
- **适配新固件协议版本**：命令字与 AT 指令集中在 `OtaProtocol`；帧长/字段变化改 `buildLongCmd()/buildDataFrame()/buildEnterBootCmd()`；上行 ACK 语义变化在 `feedRxByte()` 的 ACK 分支登记。
- **调整重试节奏/探测候选**：`otaworker.cpp` 匿名命名空间的 `kBaudCandidates`/`kBlockRetryMax`/`kUpgradeRounds`/`kForsenseWindowCount`/`kEraseAckWaitMs` 与 YModem 的 `kYm*` 常量集中一处，改值不动流程代码。
- **新增传输链路**：`Transport` 枚举加值 → `openTransport()/tx()/closeTransport()` 加分支 → `OtaPanel` 链路下拉框加项。

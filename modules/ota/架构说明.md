# OTA 升级模块（modules/ota）架构说明

## 1. 概述

`modules/ota` 是 Witt.exe 的「OTA 升级」模块，负责把 `.firmware` 固件文件通过**串口或 TCP** 下发到设备 Bootloader，完成「进 BL → 握手 → 擦除 → 64B 分块烧写 → CRC 校验 → 重启」的完整流程，并通过进度条、阶段标签与日志向用户反馈。

| 组件 | 文件 | 职责 |
|------|------|------|
| 协议层 | `core/otaprotocol.h/.cpp` | 帧格式定义、CRC32、组帧、文件名 CRC 提取（纯函数，无 UI 无连接） |
| 控制层 | `core/otaworker.h/.cpp` | 升级状态机 + ACK 解析，在工作线程内驱动整条链路 |
| UI 层 | `ui/otapanel.h/.cpp` | 链路/固件参数配置、开始/取消、进度与日志展示 |

协议参照 Linux_UATR_OTA 工具：**下行帧头 `55 AA`、上行帧头 `AA 55`**，全小端。本模块独立，不依赖 `modules/parse`。

```
┌──────────────────────────────────────────────────┐
│          OtaPanel（QWidget，UI 线程）              │
└───────────────┬──────────────────────────────────┘
                │ QThread + 跨线程信号槽（自动排队）
┌───────────────▼──────────────────────────────────┐
│   OtaWorker（工作线程：升级状态机 + ACK 解析）      │
├───────────────┬──────────────────────────────────┤
│ OtaProtocol    │ SerialConnection / TcpConnection │
│ （组帧/CRC32）  │ （common 模块，两种链路二选一）      │
└───────────────┴──────────────────────────────────┘
```

## 3. 协议层（OtaProtocol）

### 3.1 帧格式

下行帧（主机 → 设备，帧头 `55 AA`）共三种：

- `buildLongCmd(cmd)`：**34 字节** `sync(2)+id(2)+len(2)+params(24 全 0)+crc(4)`，len 固定 24（6×u32）；用于 GET_SYNC / CHIP_ERASE / GET_CRC / REBOOT 等无参命令。
- `buildDataFrame(offset, size, data)`：**81 字节** `sync(2)+id(2)+len(2)+data[64]+offset(4)+size(2)+cmd(1)+crc(4)`，len 固定 71，id 固定 `PROG_MULTI`，cmd 子命令填 0；数据区不足 64 字节补零。
- `buildResetMagic()`：**34 字节**硬复位魔术帧（id=`0x88BB`），字节内容按参考工具 `do_upload()` 原样固化。

上行帧（设备 → 主机，帧头 `AA 55`）由 `OtaWorker` 的 ACK 状态机逐字节解析（见 4.2）。

### 3.2 指令集（`OtaProtocol::Cmd`）

| 命令字 | 值 | 含义 |
|--------|------|------|
| `GET_SYNC` / `GET_DEVICE` / `CHIP_ERASE` / `CHIP_VERIFY` | 0x21/0x22/0x23/0x24 | 握手 / 读设备信息 / 擦除 APP 区 / 校验（流程中校验实际走 `GET_CRC`） |
| `PROG_MULTI` / `GET_CRC` / `REBOOT` | 0x27/0x29/0x30 | 64B 块烧写 / 芯片回算固件 CRC32 / 重启 |
| `RESET_MAGIC` | 0x88BB | 硬复位魔术帧（强制进 BL） |
| `ACK_CMD` / `ACK_CRC` / `ACK_OFFSET` | 0x0064/0x753C/0x753D | 上行应答：命令应答 / 芯片侧 CRC / 已确认 offset |
| `OK` | 0x10 | `ACK_CMD` 中 command==0x10 视为成功 |

### 3.3 校验与握手

- `crc32()`：IEEE 802.3 表驱动 CRC32，**初值 = 1**，覆盖 sync~payload（不含 CRC 本身）。
- `crc32File()`：按 64KB 分块计算整个固件文件 CRC，失败返回 0 并填 err。
- 固件文件名须含 `#CRC<十进制>`，`extractCrcFromFileName()` 提取作为升级后校验的期望值。
- `handshakeString()` 返回握手串 `"HC32MCU_FORSENSE"`；`kBlockSize=64`、`kBootBaud=115200` 为 constexpr。

## 4. 控制层（OtaWorker）

### 4.1 配置与阶段

```cpp
enum class Transport { Serial, Tcp };
enum class Phase { Idle, Connecting, Resetting, Handshaking, Erasing,
                   Programming, Verifying, Rebooting, Done, Failed };
struct Config {
    Transport transport = Transport::Serial;
    QString port;  int baud = OtaProtocol::kBootBaud; // 自动模式=应用波特率；手动=BL 波特率
    QString host;  int tcpPort = 0;
    QString firmwarePath;
    bool    autoReset = true;   // true=发魔术帧自动进 BL；false=设备已手动进 BL
};
```

对外信号：`phaseChanged(Phase, QString)`、`progress(int percent)`、`logMessage(QString)`、`finished(bool success, QString summary)`。

### 4.2 ACK 接收状态机

`feedRxByte()` 实现逐字节状态机 `WaitSync1 → WaitSync2 → WaitId1/2 → WaitLen1/2 → Payload → WaitCrc1..4`，边收边累积 CRC（初值 1）。CRC 匹配且 payload ≥ 8 字节时按 id 分发：

- `ACK_CMD`：word0 == `OK`(0x10) → 置 `m_ackOk`
- `ACK_CRC`：word1 → `m_crcAck`（芯片侧固件 CRC32）
- `ACK_OFFSET`：word1 → `m_offsetAck`（已确认烧写 offset）

### 4.3 升级流程（`start()`，worker 线程入口）

重试常量（`otaworker.cpp` 匿名命名空间）：连接 8s；握手最多 30 轮；擦除重试 3 次、ACK 超时 30s；单块重发上限 100 次、offset ACK 超时 1s；「擦除→烧写→校验」整轮重试 3 轮。

1. **连接**：`openTransport(m_cfg.baud)`——串口按 `connectToPort(port, baud, 8, 0, 0, 8s)`（8 数据位/无校验/1 停止位），TCP 按 `connectToHost(host, port, 8s)`；`waitEvent` 等连接成功。
2. **进 BL**（仅 `autoReset`）：魔术帧 ×3（间隔 50ms）→ 睡 2s；串口链路关闭后按 BL 固定速率 **115200** 重开（TCP 不切波特率）。手动模式仅提示用户确认已进 BL。
3. **握手** `syncWithBootloader(30)`：每轮先发握手串 ×10（间隔 50ms），再发 `GET_SYNC` ×3（间隔 20ms），等 `m_ackOk` 1s，失败打日志继续下一轮。
4. **加载固件**：文件名缺 `#CRC` → fail；大小不是 4 的倍数 → fail；扩展名非 `.firmware` 仅提示；本地 `crc32File()` 与文件名 CRC 比对并打日志（不一致打警告但不中止）。
5. **擦除→烧写→校验**（最多 3 轮，轮间先 `syncWithBootloader(5)` 重同步）：
   - `eraseChip()`：发 `CHIP_ERASE`，睡 2s 后等 ACK 30s，重试 3 次；
   - `programFirmware()`：按 **64B/块** 组 `PROG_MULTI` 数据帧下发，等 offset ACK 等于当前块偏移（1s 超时），未确认则重发并在重发前 `syncWithBootloader(2)` 重同步，超 100 次失败；每块成功后按已发字节发 `progress` 百分比；
   - `verifyCrc()`：发 `GET_CRC` ×10 → 睡 1s → 等 `ACK_CRC` 3s → 比较芯片 CRC 与文件名期望 CRC。
6. **重启**：发 `REBOOT` ×10 → 关链路 → `progress(100)` → `Phase::Done` → `finished(true)`。

任何阶段失败统一走 `fail()`：`Phase::Failed` + 日志 + `closeTransport()` + `finished(false)`。

## 5. UI 层（OtaPanel）

界面自上而下：链路设置（串口/TCP 切换）→ 固件选择 → 自动复位勾选（默认勾选）→ 开始/取消按钮 → 进度条 → 阶段标签 → 只读日志。波特率下拉框可编辑，预置 9600~921600，默认 115200。

- `refreshPorts()`：枚举 `QSerialPortInfo::availablePorts`，`itemData` 存 portName；无串口时填「无可用串口」占位项。
- `onBrowseFirmware()`：过滤器 `固件文件 (*.firmware);;所有文件 (*)`，选完 `updateFirmwareInfo()` 显示大小、文件名 CRC、本地 CRC 及「✓一致 / ✗不一致」（`OtaPanel` 直接使用 `OtaProtocol` 做预检）。
- `onStart()`：校验固件与链路参数后组装 `Config`——**手动进 BL 时波特率固定 115200，自动模式用用户所选应用波特率**；`new QThread` + `new OtaWorker` → `moveToThread` → `thread.started` 触发 `start()`；`setRunning(true)` 禁用配置控件、启用取消按钮。
- `onCancel()`：`QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 调 `cancel()`，并禁用取消按钮防止重复请求。
- `onFinished()`：恢复控件，按成败弹 `QMessageBox`；worker/thread 通过 `finished → thread.quit → deleteLater` 自清理。
- 析构兜底：cancel → `quit()` → `wait(3000)`。

## 6. 线程模型与取消语义

- **线程归属**：`OtaWorker` 及其在 `openTransport()` 内创建的 `SerialConnection`/`TcpConnection`（以 worker 为 parent）全部活在工作线程；worker 的信号跨线程自动排队送达 UI。
- **取消**：`m_cancel` 为 `std::atomic<bool>`；工作线程在 `waitEvent()`（QEventLoop + 50ms tick 定时器轮询 m_cancel/条件）与 `sleepMs()`（20ms 步进检查）中及时响应；每个升级轮次、每个 64B 块、每次重发前都检查 `m_cancel`，取消后统一走 `fail(QStringLiteral("已取消"))`，保证链路关闭与 `finished(false)` 必定发出。
- **单实例**：`m_worker` 非空时 `onStart()` 直接返回，一次只允许一个升级任务。

## 7. 与 common 模块的依赖

依赖方向：`ui/otapanel` → `core/otaworker` → `common/serialconnection`、`common/tcpconnection`。

OTA 支持两种下发链路，帧协议完全一致：**串口**走 `SerialConnection::connectToPort/send`，**网络**走 `TcpConnection::connectToHost/send`。两者对外信号一致（`connected`/`dataReceived`/`errorOccurred`），`OtaWorker` 用 `tx()` 屏蔽差异，仅在「自动进 BL 后切波特率」一步区分串口/TCP。模块不依赖 `modules/parse`。

## 8. 扩展点

- **适配新固件协议版本**：命令字集中在 `OtaProtocol::Cmd`；帧长/字段变化改 `buildLongCmd()/buildDataFrame()`；上行 ACK 语义变化在 `OtaWorker::feedRxByte()` 的 ACK 分支登记；块大小 `kBlockSize`、BL 波特率 `kBootBaud` 均为 constexpr。
- **新增传输链路**：`Transport` 枚举加值 → `openTransport()/tx()/closeTransport()` 加分支 → `OtaPanel` 链路下拉框加项（itemData 存枚举值）。
- **调整重试节奏**：`otaworker.cpp` 匿名命名空间的 `kSyncRoundsMax`/`kEraseRetries`/`kBlockRetryMax`/`kUpgradeRounds` 等常量集中一处，改值不动流程代码。

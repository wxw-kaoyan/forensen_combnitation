# 模拟器模块（modules/simulator）架构说明

## 1. 概述

`modules/simulator` 是 TASoftware 的「数据源模拟」模块，用于在无真实接收机时给被测设备灌数：占用两个串口，一个通过 DTR 线输出秒脉冲（PPS 上升沿，脉宽 5ms），另一个按协议库输出 GNSS 定位数据帧（NMEA 文本 / NovAtel OEM 二进制 / 本工程 AA55 自定义帧）。

| 组件 | 文件 | 职责 |
|------|------|------|
| 模拟面板 | `simulatorpanel.h/.cpp` | 串口选择、协议勾选、全局频率、启停与日志 |
| PPS 发生器 | `ppsgenerator.h/.cpp` | 高精度线程输出 DTR 秒脉冲 |
| 数据模拟器 | `datasimulator.h/.cpp` | 由 PPS 驱动、按频率调度各协议发帧 |
| 时间基准 | `simclock.h` | 系统 UTC → GPS 时间的换算 |
| 协议抽象与工厂 | `simprotocol.h`、`simprotocolregistry.h/.cpp` | `SimProtocol` 基类 + `sim_protocols.json` 驱动创建 |
| 编码器 | `encoders/` | NMEA / NovAtel / AA55 三种帧格式打包 + 小端写工具 |
| 具体协议 | `protocols/` | GPRMC、GPGGA、BESTPOSB、PSRVELB 四种报文 |

整体分层如下：

```
┌──────────────────────────────────────────────────────────┐
│              UI 层  SimulatorPanel（主窗口 simulatorTab）  │
└──────────────┬───────────────────────┬───────────────────┘
               │ ppsTick ──整秒对齐──▶ onPpsTick
       ┌───────▼────────┐      ┌───────▼────────┐
       │  PpsGenerator   │      │  DataSimulator  │
       │  PPS 串口(DTR)  │      │  数据串口(TX)   │
       └───────┬────────┘      └───────┬────────┘
               │                sendAll(): p->encode(m_clock)
               │                ┌───────▼─────────────────────┐
               │                │ protocols/（GPRMC/GPGGA/…） │
               │                └───────┬─────────────────────┘
       ┌───────▼────────────────────────▼───────────┐
       │  simclock.h（SimClock 时间基准）            │
       │  encoders/（Nmea/Novatel/Aa55 + ByteWriter）│
       └────────────────────────────────────────────┘
```

## 3. 时间基准 SimClock（simclock.h）

各协议编码时统一从 `SimClock` 取时间戳字段：

```cpp
struct SimClock {
    uint16_t gpsWeek      = 0;     // GPS 周
    uint32_t gpsWeekMs    = 0;     // 周内毫秒
    uint32_t gpsWeekSec   = 0;     // 周内秒（整秒，PPS 对齐）
    uint32_t utcTimeOfDayMs = 0;   // UTC 日内毫秒（NMEA 用）
    QDate    utcDate;              // UTC 日期（GPRMC 日期字段用）
    uint32_t timerUs      = 0;     // 上电计时(us)，保留字段
};
```

换算函数 `simClockFromUtc()`：以 **1980-01-06 00:00:00 UTC** 为 GPS 纪元，闰秒固定 **18s**（2017-01-01 起）：

```
GPS秒   = UTC秒 - GPS纪元 + 18
GPS周   = GPS秒 / 604800
周内毫秒 = (GPS秒 % 604800) × 1000 + UTC毫秒
```

`DataSimulator::onPpsTick()` 会把系统 UTC 时间**向下取整到秒**再换算，使周内毫秒整秒对齐 PPS 上升沿。若未来插入闰秒，需同步修改 `simclock.h` 中的 `leapSeconds` 常量。

## 4. 协议抽象与 JSON 配置

### 4.1 SimProtocol 基类（simprotocol.h）

```cpp
class SimProtocol {
public:
    virtual QByteArray encode(const SimClock &clock) = 0;  // 时间基准+模板参数→一帧
    QString     name;          // 协议名，如 "GPRMC"
    QString     format;        // "nmea" / "novatel" / "aa55"
    int         rateHz   = 1;  // 输出频率
    bool        hasGpsTime = true;
    bool        enabled   = true;
    QJsonObject params;        // 模板固定参数（JSON 提供，运行时可改）
};
```

### 4.2 SimProtocolRegistry —— JSON 驱动的工厂

`loadSimProtocols(jsonPath)` 读取 JSON 顶层 `"sim_protocols"` 数组，逐项调用 `createSimProtocol(cfg)`：按 `name` 匹配创建实例（`GPRMC→Gprmc`、`GPGGA→Gpgga`、`BESTPOSB→BestPosb`、`PSRVELB→Psrvelb`），未匹配返回 `nullptr` 跳过；再用 `format / rateHz(默认1) / hasGpsTime(默认true) / enabled(默认true) / params` 填充元信息。

根目录 `sim_protocols.json` 随构建拷贝到可执行文件目录（CMake `TARGET_FILE_DIR`），面板查找顺序：**程序运行目录 → 当前工作目录**。当前内置 4 条协议（GPRMC/GPGGA 1Hz，BESTPOSB/PSRVELB 50Hz），所有可变值都在 `params` 中，改 JSON 即生效、无需重编译。启动时面板的全局频率（1~100Hz）会**覆盖**各协议的 `rateHz`。

## 5. 编码器体系（encoders/）

| 编码器 | 帧格式 | 校验 |
|--------|--------|------|
| `NmeaEncoder` | `$sentence,body*CS\r\n`；`lat()`→`ddmm.mmmm,N/S`、`lon()`→`dddmm.mmmm,E/W`、`utc()`→`hhmmss.sss` | `$` 与 `*` 之间字符异或，2 位大写十六进制 |
| `NovatelEncoder` | `AA 44 12` 同步头 + 28 字节 header（msgId、消息长度、time status=160 FINESTEERING、gpsWeek、gpsWeekMs 等，小端）+ payload + CRC32 | CRC32 **初值 0**、不取反（与 rtklib `rtk_crc32` 一致） |
| `Aa55Encoder` | `AA 55` + ID(u16) + len(u16) + payload + CRC32 | CRC32 **初值 1**、不取反（与 `FrameParser::computeCrc32` 一致） |
| `ByteWriter` | 命名空间级小端写工具：`appendU8/U16/U32/I32/Float/Double` | — |

注意两种 CRC32 初值不同（0 vs 1），必须与各自解析端保持一致，不能混用。`Aa55Encoder` 目前未被任何已登记协议使用，是为本工程 AA55 帧预留的编码通道。

## 6. 具体协议（protocols/）

| 协议 | 类型 | 编码要点（params 默认值） |
|------|------|--------------------------|
| `Gprmc` | NMEA 文本 | 时间取 `utcTimeOfDayMs`、日期取 `utcDate(ddMMyy)`；status(A)、lat/lon(39.9042/116.4074)、speedKnots(0.5)、courseDeg(90.0)、magVar(0.0) E |
| `Gpgga` | NMEA 文本 | quality(1)、numSats(18)、hdop(1.0)、alt(50.0)、geoidSep(0.0) |
| `BestPosb` | NovAtel msgId=42 | solStatus(SOL_COMPUTED→0)、posType(NARROW_INT→50，支持 FIXEDPOS/SINGLE/L1_FLOAT/PPP 等映射)、height(50.0)、datumId(61 WGS84)、三轴 std(0.01/0.01/0.02)、numSats(18) |
| `Psrvelb` | NovAtel msgId=100 | velType(DOPPLER_VELOCITY→8)、horSpeed(0.5)、trackGround(90.0)、verSpeed(0.0)、latency/diffAge(0.0) |

## 7. PpsGenerator —— 高精度 PPS 秒脉冲

占用一个串口，用 **DTR 线**输出秒脉冲（上升沿 µs 级对齐、脉宽 5ms）。实现为独立 `std::thread` + `QElapsedTimer`（Windows 底层 QPC，分辨率约 100ns）：

1. Windows 下先 `timeBeginPeriod(1)` 把系统睡眠粒度提升到约 1ms（CMake 为此链接 `winmm`），并 `SetThreadPriority(THREAD_PRIORITY_TIME_CRITICAL)` 提权；
2. 首拍对齐到**下一个 UTC 整秒**，使 PPS 秒边界与系统时间一致；
3. 每拍先睡眠到目标时刻前 2ms（`kSpinMarginNs`），剩余时间忙等自旋到精确时刻再 `EscapeCommFunction(SETDTR)` 拉高 DTR（绕过 Qt 串口对象、降低切换延迟），5ms 后同法拉低；
4. 节拍采用**绝对网格**（`targetNs += 1s`），单拍过冲不向下一拍累积漂移；
5. 非 Windows 平台回退 `setDataTerminalReady()`，精度尽力而为。

## 8. DataSimulator —— 调度循环

`start(portName, baudRate=115200)` 打开数据串口（8N1、无流控），取第一个协议的 `rateHz` 作为全局频率。调度循环：

- `onPpsTick()`（与 PPS 上升沿整秒对齐）：取系统 UTC 整秒 → `simClockFromUtc` 刷新 `m_clock` → `sendAll()` 发出所有协议的**第 0 帧**（`m_framesSent=1`）；若 `rateHz>1` 启动 `m_subTimer`（`Qt::PreciseTimer`，间隔 `1000/rateHz` ms）。
- `onSubTick()`：发送第 1..N-1 帧，发满 `rateHz` 帧后停表，等待下一个整秒。
- `sendAll()`：遍历协议逐个 `encode(m_clock)`，非空帧写入串口——N 个协议 = 每秒 N×rateHz 帧。

协议对象所有权归 `DataSimulator`（`setProtocols()` 接管并在析构时 `qDeleteAll`）。

## 9. SimulatorPanel —— UI 与启动流程

界面含串口配置区（PPS/数据串口 + 波特率 9600~921600，默认 115200）、协议表格（启用勾选/协议名/格式/GPS 时间，支持全选/全不选/重新加载 JSON）、全局频率 `QSpinBox`（1~100Hz，默认 1）、启停按钮与日志区。构造时即连接 `PpsGenerator::ppsTick → DataSimulator::onPpsTick`。

启动流程 `onStartStop()`：重新从 JSON 加载 → 按表格勾选过滤（未勾选者 delete）→ 全局 `rateHz` 覆盖各协议 → 校验两串口不能相同 → 先 `m_pps->start()` 再 `m_data->start()`，任一失败统一 `stopSimulation()` 复位。

## 10. 线程模型

- `PpsGenerator` 内部运行独立 `std::thread`（`m_running` 为 `std::atomic<bool>`，`stop()` 中 `join()`）；`ppsTick` 从工作线程发射，经 Qt **队列连接**投递到主线程执行 `onPpsTick`，因此第 0 帧相对电气上升沿有一拍事件投递延迟（µs~ms 级），但 GPS 时间戳按整秒取整不受影响。
- `DataSimulator`、`SimulatorPanel` 均驻留主线程；`m_subTimer` 为 `Qt::PreciseTimer` 精度的普通 QTimer。

## 11. 依赖关系

- **对 Qt**：Widgets（面板）、SerialPort（`QSerialPort`/`QSerialPortInfo`，两个串口都由本模块直接打开收发）；Windows 下额外链接 `winmm`（仅 `timeBeginPeriod/timeEndPeriod`）。
- **对模块内其他部分**：本模块**不依赖** `commtool/common` 的收发封装——它与 commtool 是并列关系（commtool 面向真实设备连接，simulator 自持 `QSerialPort` 模拟数据源），也不被 commtool 反向引用。
- **被依赖**：`mainwindow.cpp` 创建 `SimulatorPanel` 并放入 `ui->simulatorTab`；`sim_protocols.json` 由 CMake 构建后拷贝到输出目录。

## 12. 扩展点

- **新增一种模拟协议**（同帧格式）：在 `protocols/` 新建头文件，继承 `SimProtocol` 实现 `encode()`（参考 `bestposb.h`，参数从 `params` 取并带默认值）→ 在 `simprotocolregistry.cpp` include 该头文件并在 `createSimProtocol` 加一个 `else if` 分支 → 在 `sim_protocols.json` 登记同名配置。
- **新增一种帧格式**：在 `encoders/` 新增编码器（纯静态 `pack()` 风格），必要时补充 `ByteWriter` 的小端写函数；协议 `encode()` 末尾调用 `XxxEncoder::pack(...)`。
- **新增协议参数**：直接在 `sim_protocols.json` 的 `params` 中加键，并在对应 `encode()` 中读取默认值，无需改注册逻辑。

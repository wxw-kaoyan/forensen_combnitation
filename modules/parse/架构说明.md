# 解析模块（modules/parse）架构说明

## 1. 概述

`modules/parse` 是 TASoftware（Witt）的「数据解析」层，负责把各类**原始数据**（自研 AA55 二进制帧、AG/614E-B 调试流、凯芯数据、RTCM 3.x、CAN BLF/文本日志、诺瓦泰 OEM 二进制、通用分隔文本）统一转换为**结构化帧（`ParsedFrame`）或文本表（`TextFileTable`）**，并提供查看、导出 CSV、多文件时间对齐合并（New Code）与降采样工具。

```
┌───────────────────────────────────────────────────────────────┐
│  UI 层：ParsePanel（数据解析面板，协议下拉框 + 输出 + 导出）      │
└──────────────────────────┬────────────────────────────────────┘
                           │ ParserFactory / ParserBase（多态分发，唯一入口）
                           ▼
┌───────────────────────────────────────────────────────────────┐
│  parser/ 解析核心（无 UI）                                      │
│  ├─ core/        协议定义 + AA55 帧解析 + BLF/CAN + RTCM 两级     │
│  ├─ single/      注册表驱动的标准帧协议                          │
│  ├─ debugstream/ AG 0x51~0x56 / 614E-B 调试数据流               │
│  ├─ external/    凯芯（外部 Python + MEX）                      │
│  ├─ other/       RTCM 3.x 深解码 / 诺瓦泰 OEM 二进制             │
│  └─ can/         CAN 日志协议（联试_CAN981 / 联适 / A3）          │
└───────────────────────────────────────────────────────────────┘
```

## 3. 统一入口与结果模型

### 3.1 ParseResult

```cpp
struct ParseResult {
    QString    displayText;      // 界面显示（大结果自动截断为头尾预览）
    QString    fullText;         // 完整文本（导出用）
    QString    infoText;         // 状态栏摘要（如 帧数/CRC错数、历元数）
    ProtocolID protocolId = ProtocolID::Unknown;
    QList<ParsedFrame> frames;   // 帧类分支缓存（按帧导出用）
    QString    externalCsvPath;  // 外部脚本生成的临时 CSV 路径（凯芯）
};
```

### 3.2 ParserBase 接口约定

每个协议一个子类，多态分发；虚接口：`buttonLabel()`（下拉项文字）、`category()`（下拉框分组，默认 `"其他"`）、`protocolId()`、`parse(rawData)`、`formatFrame(f)`、`csvHeader()`（默认空 = 非 CSV）。

- **统一入口** `parseToResult(rawData, filePath)`：默认实现走**帧路径** —— `parse()` 扫帧 → `csvHeader()` 非空按 CSV 逐行输出，否则按 `[#偏移] 文本` 行输出；最后统计 `infoText = "帧:N (CRC错:M)"`。
- **两类重写**：外部脚本（凯芯）与深解码（RTCM）子类重写 `parseToResult`，不走帧列表。
- **CRC 开关**：`m_skipCrc = true`（默认**不校验**），对应界面「CRC校验」勾选框默认不勾；`setSkipCrc()/skipCrc()` 读写。对累加和校验（南方激光 0x0140 / 中海达激光 0x0446 / 614P-pro 0x0199）或非标准 CRC 的文件友好。
- 静态格式化工具：`protocolNameStatic()`、`rtkStatusName()`（0=未定位/1=单点/2=伪距差分/4=固定解/5=浮点解）、`formatStatusFlags()`、`formatAttValid()`。

### 3.3 三类子类路径

| 路径 | 子类 | 说明 |
|------|------|------|
| 帧解析 | `FrameProtocolParser`、Debug/614E-B、CAN 系、诺瓦泰、A3 | 重写 `parse/formatFrame/csvHeader`，入口用默认实现 |
| 外部脚本 | `KaixinFrameParser` | 重写 `parseToResult`，调 Python 写临时 CSV |
| 深解码 | `RtcmFrameParser` | 重写 `parseToResult`，RTKLIB 解为 RINEX 文本 |

### 3.4 ParserFactory

`createAll()` 按序创建：先为 `protocolRegistry()` 每条描述符建一个 `FrameProtocolParser`，再追加 `RtcmFrameParser`、`CanRtkParser`、`LsNavParser`、`LsImuLogParser`、`DebugFrameParser`、`Eb614DebugParser`、`KaixinFrameParser`、`NovatelBestPosParser`、`NovatelPsrVelParser`、`A3Parser`。面板下拉框顺序即此顺序。

## 4. 协议定义与 core/ 基础设施

### 4.1 protocoldefs.h

集中定义 `ProtocolID` 枚举、AA55 `FrameHeader`、**全部** payload 结构体、`ParsedFrame`、RTCM 帧定义。主要 ID：

| ID | 枚举 | payload | 说明 |
|----|------|---------|------|
| 0x0002 / 0x0022 / 0x0023 | AHRS_Basic / AHRS_Extended / Quaternion | 44 / 49 / 53 B | 姿态+IMU（+flag/status）/ 四元数 |
| 0x0156 | AG_Data | 50 B | 姿态/陀螺/加计 + RTK 状态 |
| 0x0166 + len94 | FusionResult | 94 B | 组合导航融合结果 |
| 0x0166 + len105 | TiltMeasure（内部值 0x8166） | 105 B | 倾斜测量（同 ID 靠长度区分） |
| 0x0146 / 0x0140 / 0x0446 | Laser / NanfangLaser / ZhdLaser | 76 / 73 / 82 B | 激光（后两者累加和校验） |
| 0x0168 / 0x0199 | Attitude / Quat614P | 36 / 46 B | 姿态 / 614P-pro 四元数 |
| 0x0051~0x0056 | Debug_IMU…Debug_Param | 86/59/24/15/172/140 B | AG 调试流 |
| 0x0101/0x0111/0x0131 | Eb614_IMU/GPS/KF | 51/71/208 B | 614E-B 调试流 |
| 0x0109~0x0114 | Kaixin_Data | — | 外部 MEX 解析，综合 CSV |
| 0xCD01 | Can_RTK | 40 B | CAN 0x1CEBFF9A，5×8B（内部区分值） |
| 0xCD02~0xCD04 | LsNav_Gps/Imu/Param | — | 联适 0x1CFF9B9A 按包号分组（内部值） |
| 0xCD05 / 0xCD06 | LsImuLog / A3_Imu | 48 B / 64 B | 联适排查帧 / A3 CANFD 0x272 |
| 0xE042 / 0xE064 | Novatel_BestPos / Novatel_PsrVel | 72 / 44 B | OEM 二进制 MsgID=42/100 |

`ParsedFrame` 内部用匿名 `union` 挂全部协议结构体：

```cpp
struct ParsedFrame {
    ProtocolID protocol;
    uint16_t   frameId, payloadLength;
    uint32_t   crc32, crc32Expected;
    bool       crcOk;
    int        offsetInFile;
    union {
        AhRsBasic ahrsBasic;  AhRsExtended ahrsExtended;  QuaternionData quat;
        AGData agData;        FusionResult fusion;        TiltMeasure tilt;
        LaserData laser;      NanfangLaserData nanfangLaser;  ZhdLaserData zhdLaser;
        AttitudeData attitude;  Quat614PData quat614p;    CanRtkData canRtk;
        LsNavImuData lsNavImu;  LsNavGpsData lsNavGps;    LsNavParamData lsNavParam;
        LsImuLogData lsImuLog;  NovatelBestPosData novatelBestPos;
        NovatelPsrVelData novatelPsrVel;  A3ImuData a3Imu;
        DebugImuData debugImu;  …  Eb614KfData eb614Kf;  …
    };
};
```

辅助函数：`resolveProtocolID(id, len)`（0x0166 按 94/105 分流）、`isFusionResult/isTiltMeasure/isDebugProtocol/isEb614Protocol/isKaixinProtocol/isLsNavProtocol`、`protocolName()`、诺瓦泰 `novatelPosTypeName/novatelSolStatusName/novatelVelTypeName`。

### 4.2 frameparser（AA55 帧流切分）

标准帧容器（小端）：`AA 55 | ID(u16) | Length(u16) | Payload | CRC32(u32)`，帧头 6 B，总长 = 6 + payload + 4。

- `parseAll(data, skipCrc=false)`：`findNextFrame`（AA 55）→ `isFrameComplete` → 读 ID/长度 →（可选）`computeCrc32` 校验（初值 `1`、多项式 `0xEDB88320`，覆盖帧头+payload）→ `resolveProtocolID` → `parsePayload` 按 `switch` 调各 `parseXxx` 填充 union → 前进到帧尾。
- `computeChecksum8`：8-bit 累加和，供南方/中海达激光等校验定义。
- 小端读取工具 `readU16LE/readU32LE/readFloatLE/readDoubleLE` 等。

### 4.3 canblfparser（CAN BLF / 文本日志）

统一入口 `CanBlfParser`，自动识别两种存储：

1. **BLF 二进制**：跳过 144 B 文件头 → 遍历 `LOBJ` 容器（objType `0x0A` 为 zlib 压缩块）→ `decompressZlib` 前补 4 B 预估长度后 `qUncompress` → 在解压数据中扫描 `LOBJ` 内 CAN 扩展帧。
2. **文本日志**：每行 `时间,时间,0xID,XX XX …`，按裸 ID 匹配。

支持三个目标 ID（BLF 内带 `0x9C…` 扩展标志 raw 值）：`0x1CEBFF9A`（联试_CAN981，5×8B 组一历元，大端 `decodeRtkData`）、`0x1CFF9B9A`（联适 NAVDATA，`parseLsNav` 按首字节包号 1~3/4~11/12~14 分组解码 IMU/GNSS/参数）、`0x1FFFFF9A`（联适排查帧，`parseLsImuLog` 6×8B 组一条记录）。

### 4.4 rtcmparser 与 rtcm_deep_decoder 的关系

两级结构：`RtcmParser`（帧级扫描）只做 `0xD3` 前导 + 10-bit 长度切帧 + CRC-24Q（多项式 `0x864CFB`）校验，产出 `RtcmFrame` 列表；`RtcmDeepDecoder` 持有 RTKLIB `rtcm_t`，`decode()` 逐字节喂 `input_rtcm3()` 解出逐历元 `RtcmObsEpoch`（`gtime_t` + `QList<obsd_t>`），`toRinexText()/toCsvText()` 格式化。`RtcmFrameParser` 的深解码走后者；`parseRtcm()` 提供帧级扫描（供统计/格式化 `formatRtcmFrame/formatRtcmSummary`）。

## 5. 标准帧协议（single/）：注册表驱动

`protocolRegistry()` 返回 11 条 `ProtocolDescriptor`（AHRS基本/扩展、四元数、AG数据、组合导航、倾斜测量、激光、南方激光、中海达激光、姿态、614P-pro_四元数）：

```cpp
struct ProtocolDescriptor {
    QString    label;       // 下拉项标签
    ProtocolID pid;
    bool       hasCrc = false;
    QString    csvHeader;   // 空 = 原生文本格式
    std::function<QList<ParsedFrame>(const QByteArray &, bool)> parseFn;
    std::function<QString(const ParsedFrame &)> formatFn;
    QList<FieldDescriptor> fields;   // 字段显示名 + 取值 lambda
};
```

`parseFn` 统一为 `genericFrameParse(pid, data, skipCrc)`：`FrameParser::parseAll` 全扫后按 `pid` 过滤。`FrameProtocolParser` 只是描述符薄封装（`parse/formatFrame/csvHeader` 全部转发）。

注册表同时是**解析器来源**（工厂据此建下拉项）、**CSV 表头与逐行格式来源**、**字段列表来源**（`fieldsForProtocol(pid)` 经 `findProtocol(pid)` 查询）。此外 `protocolregistry.cpp` 还定义仅供字段/CSV 查询的静态描述符：`kCanRtkDescriptor`、`kLsNavImu/Gps/ParamDescriptor`、`kLsImuLogDescriptor`、`kNovatelBestPos/PsrVelDescriptor`、`kA3ImuDescriptor`（解析走各自专用解析器）。

| `Eb614DebugParser` | 614E-B调试数据流 | 0x0101/0x0111/0x0131 | 同上，显示 0x0101 | 按 ID 导出 3 个 CSV |

## 7. 解析面板（ParsePanel）与线程模型

界面结构（parsepanel.ui）：文件加载行（`loadFileButton` + `crcCheckBox` + 路径/状态标签）→ 协议 `protocolCombo`（代码动态生成）→ 只读 `outputTextEdit` → 导出CSV / New Code / 降采样 / 清空。

主流程：

1. `setupProtocolCombo()`：调 `createAll()` 读取各解析器 `category()/buttonLabel()` 后即销毁；按类插入 `── 分类 ──` 头，`m_comboToParser` 记录「下拉项 → 解析器索引」（占位/分类头为 -1 并禁用）。
2. `onLoadFileClicked()`：读文件前先 `releaseParsedData()` + `QByteArray().swap(m_rawData)` 释放旧数据；`tryDecodeHexText()` 自动把 hex 文本转二进制（含非 hex 字符则按二进制原样处理）。
3. `onProtocolComboActivated()`：未加载文件提示并复位；`skipCrc = !crcCheckBox->isChecked()`；**类型预检**——BLF 只能配 CAN 族协议（Can_RTK / LsNav_Gps / LsImuLog / A3_Imu），CAN 族协议只收 `.blf/.log/.txt`；置忙禁用下拉框。
4. 后台解析：`QtConcurrent::run` + `QFutureWatcher<ParseResult>`，`doParse()` 内部重新 `createAll()` → `setSkipCrc` → `parseToResult()`（多态分发，不识别具体协议类型）；完成后回 UI 线程写输出并缓存 `fullText / frames / externalCsvPath / protocolId`。

导出链路（`onExportClicked()` 按协议分流）：

| 场景 | 行为 |
|------|------|
| 凯芯（`isKaixinProtocol` 且有 `m_cachedCsvPath`） | 直接 `QFile::copy` 临时 CSV 到目标路径 |
| AG 调试流 | 选目录，`exportFrameCsvs()` 按 0x51~0x56 导出 `debug_0x51_组合导航IMU.csv … debug_0x56_参数.csv` |
| 614E-B | 导出 `614EB_0x0101_IMU.csv / 614EB_0x0111_GNSS.csv / 614EB_0x0131_KF.csv` |
| NAVDATA_联适 | 导出 `NAVDATA_联适_IMU_100Hz.csv / _GNSS_20Hz.csv / _参数.csv` |
| 其他 | `findProtocol(m_activeProtocolId)->csvHeader` 非空存 .csv；否则按文本前缀（`UTC天数`/`Timer(us)`/`GPS(ms)`/`GPS周秒`）启发式判断，默认 .txt |

## 8. 文本工具

### 8.1 columnextract（New Code）

- `TextFileTable`：`path/header/rows/times/timeColumn(默认0)/delimiter(默认',')/error`；`loadTextFileTable(path, timeColumn=-1)` 自动识别时间列。
- `ColumnExtractDialog`：加载多个空格/逗号/Tab 分隔文件 → 勾选导出列 → 指定主轴（`autoMasterIndex()` 默认取行数最少的低 Hz 文件）→ **按时间戳最近邻对齐合并**导出单一 CSV（`buildMergedCsv/writeMergedCsv`）。
- 异步加载/导出共用一个 `m_watcher`，`scheduleDataCleanup()` 把大数据移到后台线程释放。

### 8.2 downsampledialog

选 CSV/TXT → 预览前 50 行（`PREVIEW_ROWS`）→ 指定起始行 `m_startRow`（1-based，默认 1）与倍数 `m_factor`（默认 10）→ 从起始行起每隔 N 行取 1 行，`doDownsample()` 异步写入新文件（进度、取消、完成后统计入/出行数与体积）。

## 9. 内存管理约定

大文件解析可产生几十万帧，`clear()` 只析构元素不归还 `capacity`，残留明显。因此 `ParsePanel::releaseParsedData()` 统一用 **swap 空对象**强制归还容量：`QString().swap(m_cachedFullText)`、`QString().swap(m_cachedCsvPath)`、`QList<ParsedFrame>().swap(m_cachedFrames)`。

加载新文件前额外 `QByteArray().swap(m_rawData)`，避免新旧数据同时驻留导致内存峰值翻倍；`onClearClicked()` 同样走此路径。`ColumnExtractDialog` 的大数据清理也移到后台线程执行。

## 10. 依赖关系

本模块是**底层生产者**，依赖方向均为「上层 → parse」：

| 消费方 | 使用的 parse 接口 |
|--------|------------------|
| `analysis/core/converter.h` | `../../parse/parser/core/protocoldefs.h`（`ParsedFrame`/`ProtocolID` → 转 `DataSet`） |
| `analysis/chart/chartworkbench.h` | `columnextract.h`（`TextFileTable`/`loadTextFileTable`） |
| `commtool/realtimeparsepanel` | `protocolregistry.h` + `debugframeparser/eb614debugparser` + `protocoldefs.h`（实时流解码） |
| `commtool/streamframer` | `frameparser.h`（复用 AA55 静态切帧函数处理串口/TCP 粘包半包）+ `protocoldefs.h` |

## 11. 扩展点

- **新增标准帧协议**：`protocoldefs.h` 加 payload 结构体 + `ProtocolID` 枚举值 → `frameparser.cpp` 增加 `parseXxx` 并在 `parsePayload` 的 `switch` 登记 → `protocolregistry.cpp` 增加一条 `ProtocolDescriptor`（CSV 表头、formatFn、fields）。下拉项与解析器由工厂/注册表自动生成，无需改 UI。
- **新增 CAN/二进制特殊协议**：继承 `ParserBase`（重写 `parse/formatFrame/csvHeader` 或直接重写 `parseToResult`），在 `ParserFactory::createAll()` 追加一行；同时可在 `protocolregistry.cpp` 补一个仅供字段查询的静态描述符（`findProtocol` 登记），供导出分流与 `fieldsForProtocol()` 使用。若需多 CSV 导出，在 `ParsePanel::onExportClicked()` 增加一个分流分支。
- **新增协议字段/列**：只改对应描述符的 `fields` 与 CSV 表头即可联动显示与导出。

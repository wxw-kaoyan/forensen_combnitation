# NTRIP 模块（modules/ntrip）架构说明

## 1. 概述

`modules/ntrip` 负责程序的「NTRIP 挂站」能力：以 NTRIP 客户端身份连接 CORS 服务（Caster），接收 RTCM 差分数据流。围绕这条数据流提供三类能力：

| 能力 | 核心类 | 说明 |
|------|--------|------|
| 挂站收流 | `NTRIPLoginDialog` / `NTRIPWorker` | TCP 连接、HTTP/ICY 握手、GGA 心跳、速率统计 |
| 数据池 | `DataPool` | 线程安全环形缓冲，生产者-消费者模型 |
| 数据转发 | `ForwardTarget` / `ForwarderTableManager` | 把 RTCM 流转发到 TCP / 串口设备，可反向取 GGA |

整体分层：

```
┌──────────────────────────────────────────────────────────────┐
│                  MainWindow（主窗口 NTRIP 页）                 │
│   NtripPageManager（FixGGA/状态卡片/保存数据）                  │
│   ForwarderTableManager（转发表格/新增目标/数据查看器）           │
└───────────────┬──────────────────────────────┬───────────────┘
                │ 单例 UI                        │ forwarderRawData 等
        ┌───────▼─────────┐                     │
        │ NTRIPLoginDialog │◄────信号桥接─────────┘
        └───────┬─────────┘
                │ QMetaObject::invokeMethod（Queued，跨线程）
        ┌───────▼──────────────────────────────┐
        │ NTRIPWorker（独立 QThread）            │
        │  ├─ TcpConnection（common）→ Caster   │
        │  ├─ DataPool::feed（生产者）           │
        │  └─ ForwardTarget × N（TCP/串口转发）  │
        └──────────────────────────────────────┘
```

## 3. 三个核心类的分工

### 3.1 NTRIPLoginDialog —— 单例入口（UI 线程）

- `instance()` 单例；`closeEvent()` 仅 `hide()` 不析构（`Qt::WA_DeleteOnClose` 为 false），全程存活。
- 构造时创建 2 MB 的 `DataPool(2 * 1024 * 1024, this)` 与 `QThread`，把 `NTRIPWorker` `moveToThread` 后启动线程。
- 从 `config.json`（搜索 `applicationDirPath`、`../`、`../../`）读取 `ntrip` 节点填充 Host/Port/Mountpoint/User/Password 输入框。
- 转发管理 API（`addForwardTarget` / `removeForwardTarget` / `startForwardTarget` / `stopForwardTarget` / `enableForwarderSave` 等）全部通过 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 代理到工作线程；同时在主线程缓存 `m_forwarderConfigs` / `m_forwarderRunning` 供 UI 同步查询（运行态以状态文本含「已连接」「已打开」判定）。
- 对外只发信号：`connectionStatus`、`dataRateChanged`、`connectionStateChanged` 及 `forwarder*` 系列，worker 的信号在此桥接转发。

### 3.2 NTRIPWorker —— 工作线程执行体

槽 `start(host, port, mountpoint, user, password)` 触发 `TcpConnection::connectToHost`；`onConnected()` 后发送 NTRIP 请求；`onDataReceived()` 分两阶段：先攒 HTTP/ICY 响应头（`m_headerBuffer`），非 200 则报错断开；之后进入 RTCM 流阶段——字节计入速率统计、直接 `m_dataPool->feed(raw)`（DataPool 内部有 `QReadWriteLock`，跨线程直接调用安全）并 `emit dataReady`。

### 3.3 NtripPageManager / ForwarderTableManager —— 页面组织（UI 线程）

`NtripPageManager` 接收 `Widgets` 结构（configButton、logEdit、connectStatusLabel、rateLabel、fixGgaCheckBox、fixGgaFrame、fixLonEdit/LatEdit/HeightEdit、headerLayout），由 MainWindow 装配：

- 状态卡片随 `connectionStateChanged` 变色；速率随 `dataRateChanged` 刷新。
- 「保存数据」按钮：`DataPool::subscribe()` 后用 200 ms 定时器轮询 `read()` 写入 `.bin` 文件，停止时读出余量并经状态栏提示。
- FixGGA 联动：勾选 → `setFixGGA()` + `setUseFixGGA(true)` 并调用 `m_ftm->clearAllGgaSources()`；转发表勾选 GGA 源 → 发 `tableGgaSourceChecked()` 反向取消 FixGGA（二者互斥）。

`ForwarderTableManager` 管理转发表（列：0 类型 / 1 地址 / 2 端口或「波特率/数据位/校验/停止位」/ 3 GGA源勾选 `kGgaColumn=3` / 4 状态 / 5 操作按钮组），负责新增 TCP/串口目标对话框（TCP 默认 127.0.0.1:2101；串口默认 115200，校验 N/E/O → 0/2/3，停止位 1/1.5/2 → 1/3/2）。

## 4. 连接方式与 NTRIP 协议

- **直连**：`TcpConnection`（common）内用 `QTcpSocket` 直连 `host:port`，不使用代理、不绑定网卡。连接超时硬编码为默认参数 `connectToHost(host, port, timeoutMs = 1000)`（`common/tcpconnection.cpp`），超时发 `errorOccurred("连接超时（1秒）")` 并 `abort()`。
- **握手**：`sendNtripRequest()` 发送 `GET /<挂载点> HTTP/1.1` + `Host` + `Ntrip-Version: Ntrip/2.0` + `Authorization: Basic`（base64 用户名:密码）+ `User-Agent: NTRIP Witt/2.0`，即 NTRIP 2.0 请求；1.0 的 caster 会忽略 `Ntrip-Version` 头、也接受 HTTP/1.1 请求行，故无需版本开关。响应头兼容标准 HTTP（`\r\n\r\n` 结尾）与 ICY 单行（如 `ICY 200 OK\r\n`）两种格式；不含 `200` 则 `errorOccurred` 并断开。
- **NTRIP 2.0 分块传输**：响应头含 `Transfer-Encoding: chunked` 时置 `m_chunked`，后续 RTCM 字节先经 `dechunk()` 剥掉块头（`<十六进制长度>\r\n<数据>\r\n…0\r\n\r\n`）再进数据池——否则长度行会掺进 RTCM 流，导致转发/存档/解析全部错位。分块边界可能落在 TCP 分段中间，用 `m_chunkBuf` + `m_chunkState` 状态机跨回调续处理；块长度非法时判定服务器未分块，剩余字节原样透传。
- **收流**：TcpConnection 内部攒缓冲（≥4096 字节或 30 ms 定时）成块发出，避免逐包信号开销。收流统一走 `feedStream()`（去分块 → 速率统计 → 写 DataPool → `emit dataReady`），速率只统计去块头后的净荷。
- **GGA 双模式**：FixGGA 模式由 1 Hz 定时器生成 `$GPGGA`（时间固定 `000000.00`，历度分格式经 `toNmeaLat/toNmeaLon` 转换，XOR 校验和）；外部源模式由转发目标收到的真实 GGA 驱动——`ForwardTarget::ggaDataReceived` 直连 `forwardGGA`（同线程），不足 `\r\n` 结尾时补发。
- **速率统计**：`QTimer::singleShot(1000, onRateTick)` 自链式循环，按 B/s / KB/s / MB/s 发 `dataRateChanged`。

## 5. 数据池与转发

### 5.1 DataPool —— 多消费者环形缓冲

```cpp
QReadWriteLock m_lock;
QByteArray     m_buffer;            // 定长环形缓冲（默认 2 MB）
qint64         m_writePos = 0;      // 全局写位置
QVector<qint64> m_readPositions;    // 每个消费者的读位置
```

- `feed()`（`QWriteLocker`，任意线程安全）：写环形缓冲，解锁后 `emit dataAvailable()`。
- `subscribe()`：返回消费者 id，**读位置从当前 `m_writePos` 起步，不回溯历史数据**。
- `read(consumerId)`：一次取走自上次读取后的全部增量并把读位置前移；消费者落后超过容量时跳到 `writePos - m_capacity` 丢弃旧数据。
- `availableBytes()`：未读字节数（上限为容量）。

### 5.2 ForwardTarget —— 转发目标

```cpp
struct Config {
    Type    type = TCP;          // TCP / Serial
    QString address;             // TCP: 主机名；Serial: COM 口名
    int     portOrBaud = 0;      // TCP: 端口；Serial: 波特率
    bool    isGgaSource = false; // 是否作为 GGA 上行源
    int     dataBits = 8; int parity = 0; int stopBits = 1; // 串口专用
};
```

基类持有 `m_pool` / `m_consumerId`，提供 `enableSave/disableSave`（保存收到的原始数据）与 `extractGgaLines()`（跨 readyRead 分片拼接 `m_rxBuffer`，提取 `$...GGA` 完整行）；工厂 `ForwardTarget::create(cfg, pool, parent)` 按类型实例化 `TcpForwardTarget` / `SerialForwardTarget`。

- `TcpForwardTarget`：`QTcpSocket` 直连，`QTimer` 单发 1 s 连接超时（超时 `abort()`）；`start()` 中 `subscribe()` 后以 **`Qt::UniqueConnection`** 连接 `DataPool::dataAvailable`——防止重复启动导致信号重复连接、同一份数据被多次转发（历史教训，配合 `if (m_running) return;` 双保险）。仅在 `ConnectedState` 才 `write`。
- `SerialForwardTarget`：先检查 `QSerialPortInfo` 是否存在；`open()` 前后 `blockSignals(true/false)`，防止 open 期间 readyRead 同步触发导致崩溃。
- GGA 源模式：`onReadyRead()` 中 `emit rawDataReceived` → `saveData` → 逐行 `emit ggaDataReceived`。

### 5.3 数据查看器 DataViewerDialog —— 只追加一次的约定

`ForwarderTableManager::openDataViewer(index)` 创建查看器（`WA_DeleteOnClose`），并把 `NTRIPLoginDialog::forwarderRawData` 连接到 `viewer->appendData`。**连接的 context 用查看器自身而非常驻的 `this`**：查看器关闭析构时连接自动解除。历史教训：曾以常驻对象为 context，查看器关闭后重开旧连接仍在，导致同一数据块被追加多份。配合两层防护：`m_dataViewers` 已存在则复用不重复连接；`QObject::destroyed` 时从 `m_dataViewers` 移除。

查看器内部：200 ms 定时器批量刷新（攒 `m_buffer` 一次插入，避免高频刷 UI）、暂停/继续、转义显示（默认开：`\r`/`\n` 字面量化、不可打印字节显示 `\xNN`）、清空，底部自动跟随滚动。

## 6. 线程模型

| 对象 | 线程 | 说明 |
|------|------|------|
| `NTRIPLoginDialog` / `NtripPageManager` / `ForwarderTableManager` / `DataViewerDialog` | UI 线程 | DataPool 归属 UI 线程但靠锁保证线程安全 |
| `NTRIPWorker` / `TcpConnection` / 全部 `ForwardTarget`（含其 socket/串口） | `m_thread` 工作线程 | worker 无父对象 `moveToThread`；转发目标由 worker 创建（parent=worker） |
| 跨线程调用 | — | UI→worker 一律 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)`；worker→UI 走信号（自动 Queued） |

- `startConnection()` 先禁用 Start/Stop 按钮防重复点击。
- 析构顺序：`m_worker->stop()` → `m_thread->quit()` → `m_thread->wait(3000)`；`QThread::finished` 连接 worker 的 `deleteLater`。

## 7. 依赖关系

- `modules/ntrip` → `common/tcpconnection`（唯一对模块外源码依赖）：worker 借它建 TCP 连接；1 s 连接超时在 `tcpconnection.cpp` 的默认参数中。
- `mainwindow.cpp` → ntrip：装配 `ForwarderTableManager` 与 `NtripPageManager`，传入主窗口控件。
- 与 `commtool` **无直接依赖**：两者仅在国家层（MainWindow）会合。GGA 外部源模式的数据由转发目标设备反向提供，`NTRIPLoginDialog::forwardGGA()` 为外部模块预留透传接口（当前无模块调用）。

## 8. 扩展点

- **新增转发目标类型**（如 UDP/蓝牙）：在 `ForwardTarget::Type` 加枚举值与 `Config` 字段 → 新建子类实现 `start()/stop()/onPoolData()/onReadyRead()`（`start()` 中 `subscribe()` 并用 `Qt::UniqueConnection` 连 `dataAvailable`）→ 在 `ForwardTarget::create()` 工厂加分支 → `ForwarderTableManager` 增加对应「新增 XX 目标」入口并接入 `rebuildTable()` 的显示分支。
- **新增数据源（生产者）**：任何线程直接调 `DataPool::feed()`（如让模拟器/串口工具向池中注入数据），消费者无需改动。
- **新增消费者**：`subscribe()` 取 id → 连接 `dataAvailable`（务必 `Qt::UniqueConnection`，临时窗口以自身为 context）→ 在槽中 `read(consumerId)`。参照 `NtripPageManager` 轮询保存与 `ForwardTarget` 事件驱动两种范式。

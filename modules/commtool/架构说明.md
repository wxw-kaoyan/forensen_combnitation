# 通信工具模块（modules/commtool）架构说明

## 1. 概述

`modules/commtool` 是 TASoftware 的「通信调试工具」，对应主窗口中的 CommTool 页。它基于 `common` 基础设施层建立串口/TCP 连接，在原始字节流上做实时协议解析，并提供面向各类模组的 AT 指令收发与参数配置：

| 子系统 | 文件 | 职责 |
|--------|------|------|
| 主控制器 | `commtool.h/.cpp` | 连接管理、收发、接收区显示与落盘、指令补全 |
| 流式切帧 | `streamframer.h/.cpp` | 原始流 → 完整帧（粘包/半包/CRC） |
| 实时解析 | `realtimeparsepanel.h/.cpp` | 协议选择、帧字段实时显示、10Hz 节流 |
| AT 指令 | `atcmd/` | 指令库（at_commands.json）、指令面板、参数弹窗 |

整体分层如下：

```
┌────────────────────────────────────────────────────────────┐
│                    UI 层（QWidget / 主窗口页）               │
│   CommTool（控制器）  RealtimeParsePanel  AtCmdPanel/Dialog │
└──────────────┬──────────────────────────┬──────────────────┘
               │                          │
       ┌───────▼────────┐        ┌────────▼─────────────────┐
       │  StreamFramer   │        │  AtCmdStore（JSON 读写）  │
       │  （无 UI 纯逻辑）│        │  at_commands.json        │
       └───────┬────────┘        └──────────────────────────┘
       ┌───────▼─────────────────────────────┐
       │ common/：SerialConnection、TcpConnection（工作线程）│
       │ parse/ ：FrameParser、protocolRegistry、ParsedFrame │
       └─────────────────────────────────────┘
```

## 2. 目录结构

```
modules/commtool/
├── commtool.h/.cpp           # 主控制器：连接/收发/接收区/补全
├── streamframer.h/.cpp       # 流式帧解析器（增量缓冲 + 半包缓存）
├── realtimeparsepanel.h/.cpp # 实时解析面板（选协议 + 统计 + 节流刷新）
└── atcmd/
    ├── atcmdpanel.h/.cpp/.ui # AT 指令面板（按分类动态建 Tab）
    ├── atcmdstore.h/.cpp     # at_commands.json 读写（纯静态类）
    └── atparamdialog.h/.cpp  # 指令参数输入弹窗
```

数据文件 `at_commands.json` 位于仓库根目录，CMake 构建后拷贝到可执行文件同目录（`AtCmdStore::storePath()` 按应用目录查找）。

## 3. CommTool —— 主控制器

`CommTool` 直接持有 `Ui::MainWindow`，构造时完成全部信号槽接线，并**立即启动工作线程** `m_connThread`。布局上配置区固定宽度、接收消息区吸收多余空间。

- **连接管理**：`applyMode()` 按模式下拉框切换串口（端口/波特率/数据位/校验/停止位）与 TCP（地址/端口，默认 `127.0.0.1`，非法端口回退 2101）的控件可见性；`onConnectClicked()` 按当前模式创建 `SerialConnection` 或 `TcpConnection`（**无父对象**），`moveToThread(m_connThread)` 后经 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 在工作线程内调用 `connectToPort()` / `connectToHost()`（超时 1000ms）。连接中禁止切换模式；`disconnected`/`errorOccurred` 统一走 `destroyConnection()` 收尾并复位按钮，同时 `m_framer.reset()` 清空半包缓冲。
- **接收路径** `appendRecvData()`：累计 `m_recvBytes` 计数（KB/Bytes 显示）→ 若处于保存状态则原始字节直接写 `m_recvFile` → 若开启解析，帧交给 StreamFramer 并 `submitFrame()` 给面板（此时接收区让位静默）→ 否则按 HEX/文本显示。HEX/文本模式每段数据强制以换行结尾，接收区只保留最近 200 行（`kMaxRecvLines`，且关闭 undo/redo），避免 QPlainTextEdit 文档无限膨胀卡死。
- **发送路径** `onSendClicked()`：可选追加 `\r\n`、支持 HEX 文本（`QByteArray::fromHex`）转字节，统一经 `sendRawData()` 用 QueuedConnection 调用连接对象的 `send()`。
- **发送框补全**：`QCompleter` 汇总指令库全部指令（5 个分类 + 自定义，跨分类去重），`Qt::MatchStartsWith` 前缀匹配、`Qt::CaseInsensitive` 大小写不敏感、最多显示 12 条。候选串 = 指令名左对齐补空格到统一宽度 + 说明，选中后按固定宽度还原出指令名整行替换。`eventFilter` 在浮层可见时接管 Enter/Tab/Backtab/Esc；串口下拉框按下时自动刷新可用端口列表。
- **常用指令**：`onAddFavoriteClicked()` 把发送框中 `=` 之前的部分作为指令名、值作为参数提示，经 `AtCmdStore::addCustom()` 写入 JSON 的 `custom` 数组（全库查重）。

## 4. StreamFramer —— 流 → 帧切分

按 parse 模块的 **AA55 帧头协议**切帧：帧头 6 字节（`0xAA 0x55` + frameId(2, 小端) + payloadLen(2, 小端)），尾随 4 字节 CRC32。复用 `FrameParser` 的静态函数 `findNextFrame / isFrameComplete / computeCrc32 / parsePayload / resolveProtocolID`，与离线批处理 `parseAll` 的差别在于**保留半包**等待后续数据拼接：

```
feed(data)：
  buffer += data
  循环：
    findNextFrame() 定位 AA55，无帧头 → 只留末尾 1 字节（可能是半个 AA）退出
    丢弃帧头前噪声 → isFrameComplete()？否 → 半包，break 等下一段
    total = 6 + payloadLen + 4；超 4096（kMaxFrameLen）→ 视为误同步，跳 1 字节重找
    skipCrc=false 时计算 CRC32（覆盖帧头+payload）与尾部 4 字节小端 CRC 比对
    crcOk → resolveProtocolID(id,len) + parsePayload() 产出 ParsedFrame
    buffer.remove(0, total)
```

`feed(data, skipCrc = true)` **默认不做 CRC 校验**，与离线解析（crcCheckBox 默认不勾）保持一致，避免因 CRC 算法/初值差异导致"离线能解析、实时一帧不出"。统计接口 `framesFound()` / `framesCrcRejected()` 供状态行诊断。

## 5. RealtimeParsePanel —— 实时解析面板

面板只负责"选协议 + 开关 + 统计"，解析结果不在这里显示：`flushDisplay()` 把字段拼成"名称 + 值"文本，经 `displayTextReady()` 交给 CommTool 写入接收消息大框。

- **可解析协议清单** `streamingFrames()`：标准帧协议直接取 `protocolRegistry()`（含南方激光/中海达激光等）；调试数据流手工列出——AG 流 `Debug_IMU(0x51)/GPS(0x52)/DRTK(0x53)/OD(0x54)/KF(0x55)/Param(0x56)`、614E-B 流 `Eb614_IMU(0x0101)/GPS(0x0111)/KF(0x0131)`。凯芯/RTCM/CAN 因依赖外部 MEX、非 AA55 帧头、BLF 文件而不列入。默认选中 `Debug_IMU`。
- **字段提取** `fieldNames()/fieldValues()`：优先走协议注册表的 `FieldDescriptor`；调试流协议用 `DebugFrameParser::csvHeaderFor()/formatFrameFor()`（614E-B 用 `Eb614DebugParser`）的 CSV 表头/行拆分，名称与值列数严格一致。
- **10Hz 节流**：`kRefreshHz = 10`，`QTimer` 每 100ms 触发 `flushDisplay()`。`submitFrame()` 只更新缓存 `m_pendingValues` 并置脏标记，不直接改界面——显示刷新与数据到达率解耦，高频帧不会刷爆 UI。一次只解析选中协议，其它帧仅计数。
- **CRC 开关**：`strictCrc()` 对应"CRC"复选框，**默认不勾选**（与离线解析默认一致），CommTool 以 `skipCrc = !strictCrc()` 传给 StreamFramer。状态行会提示"帧全被丢弃（CRC 不通过）→ 取消勾选 CRC 试试"。
- **状态诊断** `updateStatus()`：显示总收帧数、当前协议命中数、流中各协议帧计数 Top6，辅助判断波特率/协议选择问题。支持暂停（冻结读数）与清空。

## 6. AT 指令子系统（atcmd/）

### 6.1 数据模型与存储 AtCmdStore

```cpp
struct AtCmdInfo {
    QString command;       // 指令名，如 "AT+SET_BAUD=" 或 "$KMDUART"
    QString description;   // 功能说明
    QString paramHint;     // 参数提示，空串表示无参
    QString format;        // 空/"AT"=AT；"KMD"=凯芯；"UNICORE"=和芯
};
struct AtCmdCategory { QString name; QList<AtCmdInfo> commands; };
```

纯静态类，读写可执行目录下的 `at_commands.json`（顶层为 `categories` 与 `custom` 两个数组，内置 5 个分类：通用AT / 芯片AT / 组合导航AT / 凯芯KMD / 和芯Unicore，另加用户自定义）。接口：`loadCategories()`、`loadCustom()`、`addCustom()`（全库查重）、`removeCustom()`、`exists()`、`storePath()`。每次读写都整体读入 JSON、改完回写。

### 6.2 指令面板 AtCmdPanel

构造时 `loadCategories()` 后 `cmdTabWidget->clear()` 移除 .ui 中的静态占位页，**按 JSON 分类动态生成 Tab**，每条指令一行：扁平按钮样式指令名（点击发送）+ 说明 + 发送箭头。

发送流程 `onSendClicked()`：

1. **格式判定**（大小写不敏感）：`format == "KMD"` 或指令以 `$` 开头 → KMD；`format == "UNICORE"` → Unicore；否则 AT 风格。
2. **参数获取**：`paramHint` 非空且无内联输入框时弹出 `AtParamDialog`；AT 指令必须带参数，KMD/UNICORE 留空表示无参查询。
3. **拼帧**：
   - AT：`CMD=param\r\n`
   - KMD：`$NAME,para*CS\r\n`，CS 为 `$` 与 `*` 之间字符的异或（不含 `$` 本身），两位十六进制大写
   - UNICORE：`CMD param\r\n`（空格分隔，无校验）
4. **确认后发送**：`QMessageBox::question` 确认（默认 Cancel），再依次发 `sendData()`（给 CommTool 下发）、`commandSent()`（回显发送框）、`statusMessage()`（接收区日志）。

### 6.3 参数弹窗 AtParamDialog

轻量 `QDialog`：指令名 + 说明 + 参数输入行（占位符为 paramHint）+ 确认/取消。标题按指令名以 `$` 开头且含"KMD"区分「凯芯 KMD 指令参数」「NMEA 风格指令参数」与「AT 指令参数」。`paramValue()` 返回去空格结果。

## 7. 线程模型

```
        UI 线程（主线程）                              工作线程 m_connThread
┌───────────────────────────────────┐          ┌────────────────────────────┐
│ MainWindow / CommTool（控制器）    │          │ SerialConnection           │
│ StreamFramer（值成员，纯逻辑）     │◄─信号槽──►│ TcpConnection              │
│ RealtimeParsePanel / AtCmdPanel…  │ Queued   │ （QSerialPort / QTcpSocket）│
└───────────────────────────────────┘          └────────────────────────────┘
```

- `m_connThread` 在 CommTool 构造时 `start()`；连接对象创建时**无父对象**，`moveToThread()` 移入工作线程，其所有方法（connect/disconnect/send）都经 `QMetaObject::invokeMethod(..., Qt::QueuedConnection)` 在工作线程内执行。
- `dataReceived / connected / errorOccurred / logMessage` 等信号自动以队列方式回到 CommTool 所在的 UI 线程。
- StreamFramer 与解析、面板刷新全部在 UI 线程完成：解析本身轻量，重的是显示——用 10Hz 节流 + 接收区 200 行裁剪保证不阻塞。
- 析构顺序：QueuedConnection 发断开 → `QThread::finished` 连接 `deleteLater` 删连接对象 → `quit()` + `wait(3000)` → 关闭落盘文件。

## 8. 依赖关系

依赖方向严格单向：`commtool → { common, parse }`，common 与 parse 不反向依赖 commtool。

- `common/serialconnection`、`common/tcpconnection`：连接基础设施， commtool 只负责创建/移线程/接线，零耦合复用。
- `modules/parse/parser/core/protocoldefs.h`：`ParsedFrame`、`ProtocolID`、帧头/CRC 常量与 `resolveProtocolID()`；`frameparser.h`：静态切帧/校验/解帧函数；`single/protocolregistry.h`：协议注册表与 `FieldDescriptor`；`debugstream/`：AG 与 614E-B 调试流的 CSV 字段。
- 数据文件 `at_commands.json` 由 CMake 构建后拷至输出目录，运行时由 AtCmdStore 按应用目录加载。

## 9. 扩展点

- **新增连接类型**（如蓝牙/UDP）：在 `common/` 仿照 `TcpConnection` 实现 QObject 连接类（connect/disconnect/send 槽 + 同一组信号）→ CommTool 的 `applyMode()` 加控件分支、`onConnectClicked()` 加创建与接线分支、`sendRawData()`/析构加对应调用。
- **新增实时解析协议**：若为标准 AA55 帧，只需在 parse 模块协议注册表登记 `ProtocolDescriptor` 与字段描述符，面板下拉框自动出现；调试流协议在 `streamingFrames()` 的 `kDbg`/`kEb` 表加一行即可（前提是 `resolveProtocolID` 能识别）。
- **新增指令分类/指令**：直接编辑 `at_commands.json` 的 `categories`，面板 Tab 与发送框补全自动更新，无需改代码。
- **新增指令格式**：在 `AtCmdPanel::onSendClicked()` 按现有 isKmd/isUnicore 模式增加分支（判定 + 拼帧规则），必要时在 `AtCmdInfo::format` 中约定新取值。
